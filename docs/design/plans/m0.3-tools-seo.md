> **ملخص للمالك:** هذه خطة الـ PR الثالث والأخير من المرحلة 0 (M0.3) حسب `docs/design/phase-0.md`: حزمة `tools`

> وJSON-LD، وقالب صفحة الأداة حسب §6.1، وقالب التقرير `noindex`)، وفحص SEO ذاتي يعمل في الـ CI ويُفشل البناء إن

**Goal:** CI renders every tool page in Arabic and English, plus the report template, and fails when any page
misses a part of the §6.1 template, its canonical, reciprocal hreflang or JSON-LD, or fails one of our own rules.

**Branch:** `phase-0/tools-seo`, stacked on `phase-0/rules-cli` (PR #2), with its own PR.

## 1. Packages

| Package | Depends on | Responsibility |
|---|---|---|
| `@arablyzer/tools` | `rules` | The tool contract (§9: slug, checks, page copy, FAQ), a copy loader, and three tools: `rtl-check`, `whatsapp-link-check`, `ai-crawler-check` |
| `@arablyzer/seo` | `tools`, `rules`, `report-schema` | Builders (URLs, hreflang alternates, JSON-LD, `<head>`), a strict Markdown subset for our copy, `renderToolPage`, `renderReportPage` |
| `@arablyzer/seo/audit` | the above, `collectors`, `engine` | The self-audit of rendered pages; a separate entry point so the site build (Phase 2) does not pull in the engine |

The engine gains `evaluatePage(page, options)`: the rule evaluation `scan()` already does, without fetching, so the
audit runs our rules on rendered HTML through the same code path as a scan.

## 2. Tool contract

```ts
interface Tool {
  slug: string                 // ASCII kebab, unique; /tools/<slug> and /en/tools/<slug> (§5.1)
  category: ToolCategory       // the 18 categories of the §5.1 table
  rules: readonly string[]     // rule ids the tool runs; a tool = a set of rules + the page template (§10)
  related: readonly string[]   // adjacent tools, linked from the page
  updated: string              // YYYY-MM-DD, shown as "last updated" (§6.1.8)
  copy: { ar: ToolCopy; en: ToolCopy }   // tools/<slug>/copy.{ar,en}.md, `reviewed` like rule copy
}
interface ToolCopy {
  title: string                // H1 in search phrasing (§6.1.1), e.g. «فحص hreflang» / "hreflang checker"
  description: string          // the line under the H1, and the meta description
  checks: string[]             // "what this tool checks" bullets (§6.1.3)
  example: { wrong: Code; right: Code }   // §6.1.4; Code = { lang: 'html' | 'robots.txt'; text }
  fix: string                  // Markdown, with code (§6.1.5)
  faq: { question: string; answer: string }[]   // §6.1.6, real text in the HTML
  methodology: string          // §6.1.8
  reviewed: boolean
}
```

- **Live examples:** a test runs each tool's rules on its own wrong and right examples. The wrong one must fail
  and the right one must pass, so the page never shows an example the tool would judge differently.
- **Copy format** mirrors rule copy: front matter, `# title`, the description paragraph, then `## ماذا تفحص`,
  `## مثال` (`### خطأ`, `### صحيح`), `## كيف تُصلح`, `## أسئلة شائعة` (`### question`), `## المنهجية`; English uses
  What it checks, Example (Wrong, Right), How to fix, FAQ, Methodology.
- **The three tools** only claim what their rules check today. `whatsapp-link-check` checks the number format; the
  encoded-message check in §5.1 comes with a later rule.

## 3. Pages

- **Paths:** Arabic at the root, English under `/en` (§1). Tool pages at `/tools/<slug>`; they link to rule pages
  at `/rules/<id>` (Phase 2) and to the tools hub at `/tools/`.
- **Site origin** is a parameter of every builder. The domain is your decision (§20.1), so tests and the CI
  audit render for the reserved `https://arablyzer.example`.
- **Tool page** (§6.1, in this order): breadcrumb; `<h1>` and the description; the tool form (URL field and
  button) before any section; `#checks`; `#example` (wrong, right); `#fix`; `#faq`; `#links` (the tool's rules and
  related tools); `#about` (methodology and `<time>` of the last update). `<html lang="ar" dir="rtl">` or
  `lang="en" dir="ltr"`.
- **Head:** title, meta description, one self-referencing canonical, hreflang `ar`, `en` and `x-default` → Arabic,
  JSON-LD `WebApplication` (free: `offers.price` 0, `isAccessibleForFree`) and `BreadcrumbList`. No
  `aggregateRating`: it would be an invented number, even though Google wants one for the software rich result.
- **Report template:** `noindex, nofollow`, no canonical or hreflang, and every value from the report escaped: a
  report quotes hostile pages.
- **Markdown:** our copy is rendered by a strict subset (paragraphs, lists, bold, inline code, code blocks, links
  to `https:` or root-relative URLs). Everything else is escaped, so copy can never inject HTML.
- **Dates** are formatted from a fixed month table («24 سبتمبر 2026» / "24 September 2026"), not `Intl`, whose
  output changes with Node's ICU data.

## 4. Self-audit

`auditToolPage(html, expected)` returns the problems it finds, each with a check id:

| Check | Passes when |
|---|---|
| `lang-dir` | `<html>` has the page language, and `dir="rtl"` for Arabic, `ltr` for English |
| `title`, `description` | both present and not empty |
| `h1` | exactly one, not empty |
| `tool-first` | the form with a URL field comes before the first `<h2>` |
| `sections` | `#checks` (a list), `#example` (two code blocks), `#fix`, `#faq` (at least one question), `#links`, `#about` (with `<time datetime>`) |
| `canonical` | exactly one, equal to the page's own URL |
| `hreflang` | `ar`, `en` and `x-default` → the Arabic URL, each once |
| `json-ld` | a `WebApplication` with the page URL, its language and a free offer, and a `BreadcrumbList` ending at the page |
| `indexable` | no `noindex` in the robots metas |
| `links` | every internal link points to a known page (tools, rules, the hub, the home page) |
| `own-rules` | none of our rules fails or errors on the page (robots.txt rules are left out: the page has none) |

`auditPair(ar, en)` adds `reciprocal`: both pages list the same alternates. `auditReportPage(html)` requires
`noindex`. The auditor is tested first on a hand-written right pair and on wrong pages made from it, one defect
each; then CI runs it on every rendered page (`pnpm seo:audit`). In Phase 2 the same checks run on Astro's `dist/`.

## 5. CI

Adds the step "SEO self-audit" (`pnpm seo:audit`). The owner's Arabic review job also covers tool copy.

## 6. Commits

docs plan → engine `evaluatePage` → tools contract and loader → one commit per tool → seo builders and Markdown →
page renderers → auditor (wrong pages first) → self-audit script and CI → docs.
