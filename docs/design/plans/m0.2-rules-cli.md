> **ملخص للمالك:** هذه خطة الـ PR الثاني من المرحلة 0 (M0.2) حسب `docs/design/phase-0.md`: حزمة `collectors`
> (من البايتات إلى الحقائق بلا شبكة)، القواعد العشر مع fixtures ونصوص عربية وإنجليزية، حزمة `engine` (رابط ←

> قرارك مجموع في القسم الأخير.

**Goal:** `pnpm arablyzer <url> --json` prints a report that validates against `report.schema.json`, and every
one of the first ten rules has a wrong and a right fixture that CI checks over real HTTP.

**Branch:** `phase-0/rules-cli`, stacked on `phase-0/foundation` (PR #1), with its own PR (owner: "do the best
thing", 2026-09-24).

## 1. Packages

| Package | Depends on | Responsibility |
|---|---|---|
| `@arablyzer/collectors` | `parse5` | Bytes → facts. No network. `http` (headers, `Link` header), `html` (WHATWG encoding sniffing, parse5 tree, elements with selector, location and snippet), `text` (visible text, Arabic/Latin letter counts), `robots` (RFC 9309 parser, 500 KiB) |
| `@arablyzer/rules` | `collectors`, `report-schema`, `libphonenumber-js` | The `Rule` contract (§10), one folder per rule, copy loader, pure helpers (robots matcher, language → script, ISO code lists, WhatsApp links, strict JSON checker), AI crawler data |
| `@arablyzer/engine` | `egress`, `collectors`, `rules`, `report-schema` | `scan(url)` → `Report`: fetch the page and (when a selected rule needs it) robots.txt through `safeFetch`, collect, run rules, render messages, fingerprint, sort, validate |
| `@arablyzer/cli` | `engine`, `egress`, `rules`, `report-schema` | `arablyzer <url> [--json] [--lang ar\|en] [--rules id,…] [--fail-on <severity>] [--timeout 30] [--allow-private]`; esbuild bundle for e2e |

No dependency cycles: rule tests build evidence from fixture files with the collectors; the engine test serves the
same fixtures over HTTP.

## 2. Contracts

```ts
// collectors
interface PageInput { url; status; headers: [name, value][]; body: Uint8Array }
interface PageFacts { url; status; headers; contentType; mimeType; isHtml; linkHeaders; html: HtmlFacts | null; text: TextFacts | null }
type RobotsFacts =
  | { outcome: 'fetched'; url; status; robots: RobotsTxt; truncated }   // parse and match
  | { outcome: 'unavailable'; url; status }                              // 4xx (not 429), > 5 redirects: allow all
  | { outcome: 'unreachable'; url; status; reason }                     // 5xx, 429, network: disallow all
  | { outcome: 'failed'; url; code }                                     // Arablyzer could not check: rule = error

// rules (§10, unchanged; `messages` added so copy and detector cannot drift)
interface Rule {
  id; version; category; severity; wcag?; manualCheck?
  needs: ('http' | 'html' | 'text' | 'robots')[]
  messages: readonly string[]                  // message ids the detector may return
  appliesTo(page: PageFacts): boolean
  detect(evidence: { page: PageFacts; robots?: RobotsFacts }): DetectorFinding[]
  copy: { ar: RuleCopy; en: RuleCopy }         // loaded from copy.ar.md / copy.en.md
}
interface DetectorFinding { message; values?; url?; selector?; snippet?; location?; key? }  // data only
```

- **Status:** a rule needing `html`/`text` on a non-HTML or non-2xx page → `not-applicable`; `appliesTo` false →
  `not-applicable`; robots needed but `failed` → `error` (scan `partial`); `manualCheck` → `needs-review`;
  findings → `fail`; else `pass`. A rule never passes silently when its data is missing.
- **`appliesTo` sees the whole page**, so "nothing to check" (no WhatsApp links, no hreflang, no JSON-LD) is
  `not-applicable`, not a misleading `pass`.
- **Messages** come from the copy files: `### <message-id>` under the messages section, `{placeholder}` filled from
  `values`. Backticks are markdown only and are dropped from the plain-text message.
- **Fingerprint:** first 16 hex of SHA-256 over rule id, URL, selector, message id and the detector's `key`. Line
  numbers are left out, so an edit elsewhere on the page does not change it.
- **Order:** `rules[]` by id; findings by severity, rule id, line and column, then in the order the rule reports
  them. At most 20 findings per rule; the rest are counted in `findingsOmitted`.
- **Notices** are mapped from egress error `code`s only; a resolved address never reaches the report (M0.1 review).

### Copy files

```markdown
---
reviewed: false          # copy.ar.md only; the owner sets true after reading the Arabic
---

# <title>

## الرسائل / ## Messages
### <message-id>
<one sentence with {placeholders}>

## لماذا يهم / ## Why it matters
## كيف تُصلح / ## How to fix
## كيف نكشف / ## How we detect
## المراجع / ## References
```

The completeness test checks: folder name = id, semver, both copies parse with every section, the same message ids
as the rule declares in both languages with the same placeholders, at least one reference link, at least one
`wrong*` and one `right*` fixture. A separate CI job, **Arabic copy review**, stays red while any `copy.ar.md` says
`reviewed: false` (design decision 7).

## 3. The ten rules — detection details

| Rule | Detection |
|---|---|
| `ar-html-lang` | More than half of the letters in visible body text are Arabic-script, and `<html lang>` is missing/empty or its language is not written in Arabic script (a list of Arabic-script languages, or an explicit `-Arab` script subtag; an explicit other script such as `ar-Latn` fails). `meta http-equiv=content-language` is reported as context only: screen readers use `lang` |
| `rtl-html-dir` | Same Arabic-script majority, and `<html dir>` is not `rtl`. Variants: missing, other value (`ltr`, `auto`), set on `<body>` only |
| `ar-latin-punctuation` | Arabic-script majority; in visible text outside `code/pre/kbd/samp`, an Arabic letter (optionally followed by harakat or tatweel) directly followed by `,` `;` `?`. Digits and Latin letters before the mark never fire (`1,500`, `React, Vue`) |
| `whatsapp-link-format` | `<a>`/`<area>` to `wa.me/<n>`, `wa.me/c/<n>`, `api.whatsapp.com/send?phone=`, `web.whatsapp.com/send?phone=`, `whatsapp://send?phone=`. Fails when the number has anything but ASCII digits (`+`, spaces, dashes, brackets), uses Arabic-Indic digits, starts with `0`, is not a possible international number (libphonenumber-js lengths), or carries a trunk `0` after the country code and is invalid. Links without a number (`wa.me/message/…`, `wa.me/?text=`) are skipped |
| `hreflang-invalid-code` | `<link rel=alternate hreflang>` in the head and `Link` headers. Valid: `x-default`, or ISO 639-1 language + optional ISO 15924 script + optional ISO 3166-1 alpha-2 region (Google's documented forms; `es-419` is named as unsupported). Code lists are generated from the IANA registry and cross-checked against a second source |
| `robots-blocks-googlebot` | RFC 9309 + Google's documented behaviour: specific group over `*`, groups for the same agent merged, longest match wins, ties go to allow, `*` and `$`, `/robots.txt` always allowed, Google's typo and missing-colon leniency. 5xx, 429 and network failures = disallow all; 4xx and > 5 redirects = allow all. Uses the final URL |
| `robots-blocks-ai-search` | Same matcher for each AI **search** crawler in the data file (OAI-SearchBot, Claude-SearchBot, PerplexityBot). Training and user-fetch crawlers are facts only (`facts.robots.aiCrawlers`) |
| `page-noindex` | `noindex`/`none` in `<meta name=robots\|googlebot>` or `X-Robots-Tag` (repeated headers, comma lists, `googlebot:` scoping; other agents ignored). Any 2xx page, HTML or not |
| `canonical-conflict` | Distinct absolute URLs (fragment removed) among `<link rel=canonical>` in the head (resolved against `<base>`) and `Link: rel=canonical` headers. Google ignores all of them when they disagree |
| `jsonld-syntax-error` | Each non-empty `<script type=application/ld+json>` is checked by a strict RFC 8259 validator that reports the kind (trailing comma, unexpected character, raw control character in a string, bad escape, unexpected end) and the document line/column. Engine error text is never used, so Node 22 and 24 give the same report |

AI crawler tokens and purposes were checked on 2026-09-24: Anthropic from its help-center page; OpenAI, Perplexity
and Google-Extended from excerpts of their official pages (the build environment's network policy blocked the
pages themselves). Only these nine tokens are listed; others are added once checked.

## 4. Fixtures and tests

- **Per rule** (`packages/rules/src/rules/<id>/fixtures/<name>/`): `index.html`, optional `robots.txt`,
  `fixture.json` (server overrides), `expect.json` (`{"alsoFails": [...]}` when a wrong fixture must also fail a
  related rule, e.g. `User-agent: *` + `Disallow: /` also blocks AI search crawlers).
- **Rule unit tests** (`rule.test.ts`): evidence built from fixture files through the same collectors, plus
  hand-written edge cases.
- **Engine sweep** (HTTP): every `wrong*` fixture fails its rule and nothing else (except `alsoFails`), every
  `right*` fixture passes its rule and fails none, every report is `complete` and validates with Zod and Ajv.
- **CLI e2e** (`test:e2e`): esbuild bundle, then every fixture site through `node dist/arablyzer.mjs --json
  --allow-private`, validated with Ajv; exit codes, `--fail-on`, `--rules`, `--lang`, blocked URLs.

## 5. CI

Adds: e2e step (`pnpm test:e2e`) and an **Arabic copy review** job. Rule tests run inside `pnpm test:unit`.

## 6. Commits

docs plan → collectors (http/link, encoding + html, text, robots) → rules framework → engine → CLI → one commit
per rule (wrong fixture + failing test, right fixture, detector, Arabic copy, English copy) → CI → docs.

**Changes from the design, and why**

- `Rule.messages` added to the §10 contract, so the copy files and the detector cannot drift apart.
- `expect.json` in a wrong fixture lists related rules it must also fail: `User-agent: *` + `Disallow: /` and a 503
  robots.txt block AI search crawlers as well as Googlebot. A Googlebot-only fixture checks rule 6 on its own.
- hreflang also accepts an ISO 15924 script subtag (`zh-Hant`), which Google documents.
- The fixture server answered 404 for a route with an inline body and no status; it now answers 200, as its config
  docs say. Rule tests read fixtures through the same resolver, without HTTP.
- Findings built from text (punctuation) carry a line but no column: entities make decoded columns inexact.
- The CLI adds `https://` to a bare host. Exit code precedence: a failed scan is 2; a rule failing at `--fail-on` is
  1 even when the scan is partial; otherwise a partial scan is 2.
- The Arabic review gate is its own CI job, so the code checks stay readable while the owner reviews.
