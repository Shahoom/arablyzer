# M4.8 Owner admin panel — Implementation Plan

> **ملخص للمالك:** لوحة إدارة لك وحدك على `/admin`: ترى كل المستخدمين وما يستعملونه (مواقع، فحوصات، مراقبات، زحف، PDF، مفاتيح API)، وتوقف حساباً أو تسحب جلساته أو تلغي مفتاحاً أو تغيّر حدوده أو تحذفه، وكل عملية تُسجَّل في سجل تدقيق يبقى سنة. من هو الأدمن يُحدَّد بمتغيّر بيئة واحد فقط (`ARABLYZER_ADMIN_EMAILS`) ولا توجد واجهة تمنح الأدمن لأحد. لمن ليس أدمن الصفحة غير موجودة (404). **ينتظرك:** وضع بريدك في `ARABLYZER_ADMIN_EMAILS` على الخادم، وقراءة النص العربي الجديد (`reviewed: false`).

**Goal:** the owner signs in with Google, opens `/admin`, sees every account and what it uses, and can suspend, revoke, override limits, or erase an account; every action is audited. Nobody else can tell the panel exists.

**Architecture:** server-rendered HTML from the API (`apps/api/src/admin/*`), not Astro pages: the site is static, and a static page would exist for everyone. The API answers `404 {"error":"not-found"}` (the same body as any unknown route) unless every guard passes. No script: forms, `<details>` confirmations, inline-SVG sparklines, one stylesheet served by the API itself, a CSP of `default-src 'none'; style-src 'self'; form-action 'self'`. Caddy sends `/admin*` to the API like `/api/*`. `robots.txt` says nothing of it (a `Disallow` would name it); every answer carries `X-Robots-Tag: noindex`, and it is in no sitemap.

## Contracts

**Who is admin.** `ARABLYZER_ADMIN_EMAILS`: comma-separated, lower case, exact match on the signed-in account's Google-verified address (`emailVerified === true`). Unset or empty: no admin, nothing mounted. An entry that is not one address, or has an upper-case letter, stops the start. No route and no UI grants admin.

**Guard, in order** (each failure before the last is the same 404 and does no database work beyond the session read): accounts on → a session cookie → a session → not suspended → email in the list → session younger than 12 h (else `302 /admin/reauth`, a page that signs the session out and sends the admin to the sign-in page) → per-admin limit (429) → route. A visitor who keeps probing is counted by the same visitor key as sign-in and keeps getting 404.

**State-changing routes** are `POST`, from the site's origin (`Origin` equals `ARABLYZER_SITE`; `Sec-Fetch-Site: cross-site` refused), with a `confirm=yes` field the in-page confirmation sets; deleting an account also needs the account's address typed. Each writes one `admin_audit` row **before** it acts (a failure after it leaves a row for an action that did not finish, never an action with no row); the actions are idempotent, so the admin repeats it.

| Route | Does |
|---|---|
| `GET /admin` | Overview |
| `GET /admin/users?q=&page=` | Search (address or name), 25 a page, newest first |
| `GET /admin/users/:id` | Detail: profile, plan and usage, sites, recent scans, monitors, crawls, PDFs, key prefixes, sessions, its audit |
| `POST /admin/users/:id/suspend` · `/unsuspend` | Sets `suspended_at`; suspending also revokes every session |
| `POST /admin/users/:id/revoke-sessions` | Deletes the sessions |
| `POST /admin/users/:id/keys/:keyId/revoke` | Revokes one API key |
| `POST /admin/users/:id/overrides` | Sets or clears (blank) the six overrides |
| `POST /admin/users/:id/delete` | The existing erasure path (`beforeDelete` chain), then the account |
| `GET /admin/scans?state=&host=&page=` · `POST /admin/scans/:id/delete` | Recent scans, anonymous and account; top hosts; delete a report |
| `GET /admin/audit?page=` | The audit log |
| `GET /admin/settings` | Read-only: effective plan numbers, flags, versions |
| `GET /admin/assets/admin.css`, `GET /admin/reauth`, `POST /admin/signout` | Stylesheet; sign in again |

**Language.** Arabic by default, `?lang=en` for English; it rides along in links. All copy is `packages/i18n/src/admin.ts`, `reviewed: false`.

## Data

`admin_user_state` (one row per user that has anything: `user_id` PK → `users` cascade, `suspended_at`, `last_sign_in_at`, `overrides jsonb`, `updated_at`) and `admin_audit` (`id`, `at`, `actor_id`, `actor_email`, `action`, `target_id`, `target_email`, `detail jsonb` of numbers and words only, `network` = the admin's IPv6 /48 or IPv4 /24). The audit is **not** keyed to `users`: it outlives an erased account. Erasure (`eraseUser`) deletes the state row (cascade) and rewrites the user's audit rows: `target_email`/`actor_email` become null and `target_id`/`actor_id` become `erased:` plus the first 32 hex of the SHA-256 of the old id. The audit's sweep deletes rows older than 365 days, hourly with the sessions' sweep. The worker's role gets nothing on either table (no default privilege is given to it); `provision.test.ts` pins it.

**Overrides** (`scansPerDay`, `savedSites`, `monitoredSites`, `crawlPages`, `pdfPerMonth`, `whiteLabel`) are read first by `planOf`, which is now `async` and reads `PlanCatalog.overrides`, so every quota check (scans, saved sites, monitors, crawls, PDFs, keys, the scheduler and the runners) sees them with no other change. `scansPerDay` is a window of N scans over 86 400 s and is at least 1 (suspend to block). A failed lookup falls back to the plan, never to a refusal. The scan bucket refills at the new rate, so a raised number fills over time rather than at once.

**Suspension.** Better Auth's `session.create.before` refuses a session for a suspended user (sign-in, One Tap, Google callback); `readSession` treats a suspended user's cookie as none (so `require` answers 401 and `identify` is anonymous); the v1 API key gate answers 401; suspending deletes the sessions at once. A suspended person can still use the free anonymous scan form, as any visitor can: nothing identifies them there.

## Tasks

1. `packages/plans`: `overrides.ts` (`PlanOverrides`, `applyOverrides`, `sanitizeOverrides`), `PlanCatalog.overrides?`. Tests.
2. `packages/store`: schema, migration `0009_admin`, `AdminData` (memory, PostgreSQL), exports; the services test and `provision.test.ts` lines.
3. `apps/api`: `planOf` async at every call; auth hooks; suspended in `readSession` and the v1 gate; `config.ts` wiring (`ARABLYZER_ADMIN_EMAILS`, one `erase` chain shared by the account's deletion and the admin's); audit sweep.
4. `apps/api/src/admin/*`: guard, routes, views, stylesheet; `packages/i18n/src/admin.ts`.
5. `infra`: Caddy route, compose and `.env.example`, README.
6. Tests (`apps/api/test/admin.test.ts`): 404 on every route for a non-admin and for a signed-out visitor; stale session redirected; suspended blocked at sign-in, keys and account scans; overrides respected; erasure scrubs audit and overrides; the guard's order; no `style=` and no script in any page.

1. On the server: `ARABLYZER_ADMIN_EMAILS=<your Google address>` (lower case); redeploy. Sign in with Google, open `/admin`; sign in again after 12 hours.
2. Read the Arabic in `packages/i18n/src/admin.ts` and set `reviewed: true`.
