# Arabic-native features

Fourteen features that only make sense for Arabic pages (§1 to §6, then §7 to §14 from the second branch). Each says what it decides, where it stops, and what it depends on. All the words are Arabic first and `reviewed: false` until the owner reads them. None of them is deducted from the score except the two rules marked as such in §4 and §5.

## 1. Arabic font slimmer (`ar-font-subset-savings`, tool `arabic-font-slimmer`)

- **Decides:** for each Arabic web font file the render loaded, the characters of the page's own Arabic text set in it (up to 400) and what a WOFF2 subset of those characters, with the shaping tables kept, would weigh. The rule reports files whose subset saves most of their size.
- **Limits:** the subset is made when the visitor presses download (`apps/api/src/fonts.ts`), from the font file on the owner's site, and is not stored. It is made from one page's text, so a font used on other pages needs their characters too (the card says so). Fonts the scan could not read have no subset.
- **Depends on:** the render's `files` step, `subset-font` (HarfBuzz), the font file being fetchable through the egress rules.

## 2. Arabic spelling search test (`search-spelling-variants`)

- **Decides:** asks the site's own search for a few words of the page and for their spelling variants (ة/ه, ى/ي, hamza forms, tatweel, diacritics, the other digit set), then compares what comes back with the plain spelling. A variant that finds fewer results than the word is "lost".
- **Limits:** at most 12 requests, 400 ms apart, 45 s in all, robots.txt respected; one of the requests is a nonsense query that tells "no results" pages from the rest. The number of results is read from the first page of the answer, so it is a floor. Arabizi is shown and not counted. A site with no search form and no known platform search address is not tested.
- **Depends on:** the page's HTML for the form, the platform check for WordPress-style addresses, `safeFetch`.

## 3. Country fit «ملاءمة البلد» (rule `country-fit`, rule `sar-sign-font`, tool `country-fit`)

- **Decides which country** (SA, AE, EG, KW, QA, BH, OM, JO, MA) from what the page says: the ccTLD, the region of `lang` and `hreflang`, a currency that belongs to one country (ر.س, SAR, د.إ, ج.م, ...), and calling codes of the phone numbers it shows. A country is named only when at least two kinds of evidence agree and it outweighs every other country by two. One kind alone is `thin`, and ties are `unclear`: both say so and give no percentage. It never guesses.
- **Scores the fit** over the items the page has something to judge for, each `ok`, `gap` or `unknown` (unknown is not counted): the currency of its prices and the sign; phone numbers with the country code; the digit style the country reads (Latin in the Maghreb, either elsewhere); a VAT statement for SA and AE; Hijri dates where expected; the region of the language tag. "Ready X% for <country>" is shown with three or more items judged.
- **The riyal sign:** U+20C1 (Unicode 17, 2025) draws an empty box in a font that predates it. The browser reports every element whose own text has it, with its font-family; the font coverage the render reads from the page's font files now keeps U+20C1 beside the Arabic blocks. `sar-sign-font` (minor) walks the font-family list as the browser does, and reports when web fonts come first and none has the sign. A list with no web font is not judged: only the visitor's device can answer.
- **Limits:** text in images, prices written by scripts the HTML does not show (the rule reads the HTML as sent), a multi-country site, and countries outside the nine. Information, never deducted.
- **Depends on:** `packages/rules/src/lib/country.ts`, the render's `arabicFontCoverage`.

## 4. AI readability of Arabic «قابلية قراءة الذكاء الاصطناعي للعربي» (rule `ar-ai-readability`)

- **Decides:** six kinds of Arabic text that read the same to people and differently to search indexes, retrievers and tokenizers. One finding for each kind found, with the count, the first example and a fix: tatweel inside words; invisible characters (ZWSP, word joiner, a stray BOM, and LRM, RLM or ALM between two letters or digits); Arabic-Indic and Latin digits inside one number; text thick with diacritics (a paragraph of 20 letters or more where marks are a quarter of the letters, reported at 100 such letters); letters in the presentation forms (U+FB50 to U+FEFE, leaving out the ornate parentheses and ﷺ ﷻ ﷼ ﷽); and Arabic that looks to be only in pictures (fewer than 60 Arabic letters in the text, and image alts that are Arabic sentences of 8 words or more).
- **Limits:** text as the server sends it (no scripts), code tags left out, Quranic text left out of the diacritics count. "Only in pictures" is a hint from alt texts: the pixels are not read. Tatweel and digits overlap `ar-tatweel` and `ar-digits-mixed` (which judge the page as a whole), so a page can fail both; the fixtures say so (`expect.json`). Minor.
- **Depends on:** the text segments collector.

## 5. Icons that point against their button «الأيقونات المعكوسة» (rule `rtl-icon-role`)

- **Decides:** in the rendered page, for each control (`a`, `button`, `[role=button|link]`, or a class with next or prev) in right-to-left text: its role from its label (`aria-label`, `title`, text), `rel` or class (التالي, المزيد, next, السابق, رجوع, back, ...), and where its icon points on screen: an icon-font class (`fa-arrow-right`, `bi-chevron-left`), a Material name, an SVG's `<use>` href or data attribute, or an arrow character. The direction is turned by a mirroring transform on the icon, its `::before` or `::after`, or three ancestors. It reports a control whose every icon points against its role: right for "next", left for "back". Moderate.
- **Low false positives by construction:** nothing is judged without both a role and an icon of known direction; a control whose label has both roles, or is left to right, is skipped; and when a stylesheet of the page sets what an icon class draws for right to left (`[dir=rtl] .fa-arrow-right::before { content }`), classes say nothing and the page is not judged by them. An icon the older `rtl-mirrored-icons` (review) would also list is left to this rule.
- **Limits:** an inline SVG with no name and no class is not read (its path would have to be); cross-origin stylesheets cannot be read for the swap check; icons drawn as background images are not seen.
- **Depends on:** the render (`roleIcons` in the measure step, three engines).

## 6. Arabic X-ray «أشعة الحرف العربي» (report card, fact `xray`)

- **Decides:** in each engine, the pass goes through the page's Arabic words and calls a word broken when it has a letter no font in its element's font-family list draws (the judgement of `ar-font-missing-letters`, made from the web fonts' coverage), or U+FFFD. It keeps the counts for the whole page and the boxes of the broken words that stand in the first screen (up to 40). The card draws a ring round each over the engine's picture, as SVG over the stored image, in the browser. **Arabic integrity** = the share of Arabic words drawn correctly across the engines (broken words over all words counted, never 100 while one is broken).
- **Storage:** one JPEG of the first screen (the 390 x 844 render viewport, CSS pixels) per engine, at quality 55, or 35 when over 70,000 bytes, and none when still over. It is carried in the report as a `data:` URL, at most about 94 KB, 3 engines at most, so retention (`deleteOlderThan`) and the owner's delete token cover it with nothing else to track. The CSP gains `data:` in `img-src` for it. The scanner asks for it in whole scans only; a tool's scan drops it.
- **Limits:** the judgement is the web fonts' and the replacement characters'; what a visitor's own fonts draw is unknown. Pages with more than 20,000 Arabic words are counted to that point (`truncated`). The picture is the first screen only; broken words below it are counted and listed as a number.
- **Depends on:** `fontCoverage` and the usual render, JPEG screenshots of Playwright.

## 7. Brand name consistency «اسم العلامة» (rule `brand-name-consistency`)

- **Decides:** the brand's name is read from `og:site_name`, the Organization and WebSite JSON-LD (`name`, `alternateName`), logo alt texts and the footer's copyright line; the title and the h1 are read only for mentions. Arabic is folded (hamza forms, ta marbuta, alef maqsura, tatweel, diacritics, digits), Latin ignores case, punctuation and spaces (`nameKey`). Within one script and one kind every naming source is held against the most trusted one of the kind: the company's names (Organization, copyright line) together and the site's (WebSite, `og:site_name`, `alternateName`, logo) together, since a company's name may rightly differ from its product's (this site's own Organization is CloudTopia, its WebSite Arablyzer). A name that is neither equal to the reference nor part of it is a `disagree`; equal once folded but written differently (Arabic only, any sources) is a `spelling`. When the page names its brand in Arabic and in Latin letters (two different sources) and no JSON-LD node pairs them, `alternate-missing`. Minor.
- **Limits:** an Arabic name is never compared with a Latin one (that would need transliteration); the title and the h1 can only show a spelling difference; a footer line is read by a few patterns (`©`, `جميع الحقوق محفوظة`) and the first one found.
- **Depends on:** the HTML and text collectors; nothing outside the page.

## 8. Dialect and register «اللهجة» (rule `dialect-register`, `facts.dialect`, an item of `country-fit`)

- **Decides:** the page's Arabic is classified as Modern Standard, Gulf, Egyptian, Levantine or Maghrebi by counting words from a compact lexicon (`packages/rules/src/lib/dialect.ts`): words only one dialect writes (Egyptian إزاي، عايز، دلوقتي، كده، ليه، فين، علشان; Gulf وايد، شلون، ابغى، وش، الحين، شنو; Levantine هلق، شو، بدي، هيك، كتير، منيح; Maghrebi بزاف، واش، ديال، كيفاش، دابا، غادي), spelled in the folded letters of `normalizeArabic`. Words two dialects share (مش، شوي، وين، عشان، ليش) and words that are also ordinary Modern Standard (دول، خالص، ماشي، أبي، آية) are left out. A dialect is called when at least 3 of its words are found and they are a fifth of all the telling words (Modern Standard function words, such as الذي and لقد, count as the other side); else the text is Modern Standard. A word quoted in «» or “” is mentioned, not written in, and is not counted (a page about dialects quotes them). Below 80 Arabic words there is no label and the report says "too little text". Findings: the dialect is not the speech of the country the page is for (named by two kinds of evidence, as in §3), headings and body in different registers (headings read on 8 words, one marker), two dialects mixed. Minor. `facts.dialect` carries the mix, the markers seen and whether it fits; `country-fit` has a `dialect` item (a dialect that is not the country's is a gap; Modern Standard is nothing to judge by).
- **Limits:** a sample of words, not a dictionary or a language-ID model: colloquial text without these words reads as Modern Standard; Iraqi markers are counted as Gulf; Levantine is matched to Jordan alone of the nine countries.
- **Depends on:** the text collector, `lib/country.ts`.

## 9. Arabizi look-alike domain radar «رادار الدومينات الشبيهة» (tool `lookalike-domains`, rule `lookalike-domains`)

- **Decides:** up to 100 names near the domain (`generateLookalikes`): the same label on other suffixes (com, net, co, org and the Arab ccTLDs), Arabizi digit swaps both ways (2 and 3 for a, 5 for kh, 6 for t, 7 for h, 9 for q), a letter left out, doubled or swapped, a neighbouring key, a hyphen, confusable letters (rn/m, l/i/1, o/0), in a fixed order. The A and MX records of each are asked of the DoH resolver's JSON API (Cloudflare by default, `ARABLYZER_DOH_URL`), five at a time with a 40 ms pause. For the names that resolve (mail first), at most 12 are asked of crt.sh (`?q=<name>&output=json`) one at a time, 1.5 s apart across the whole process, 15 s each; the first certificate's date, and "recent" when it is under 90 days old. Answers are cached for a day in memory. A finding for each registered name: `fresh`, `mail` or `registered`. Minor.
- **Limits:** only the names it generates; a registered name with no A or MX is not seen; crt.sh is free and errs under load (two failures in a row stop asking it, and the notice says so); no look-alike site is ever opened. Tool-only (never in a whole scan).
- **Depends on:** `safeFetch` (egress rules), Cloudflare DoH, crt.sh.
- **Cost:** none; about 200 DNS requests and 12 crt.sh requests a scan.

## 10. Arabic PDF forensics «فحص ملفات PDF العربية» (tool `pdf-forensics`, rules `pdf-arabic-text`, `pdf-metadata`)

- **Decides:** up to 3 distinct links ending in `.pdf` (the page's own domain first) are fetched one at a time through the egress rules as ArablyzerBot, after the robots.txt of each file's own host allows it, at most 15 MB each (the body is read one byte past the cap, so a file that fills it is "too large"), and only if it starts with `%PDF-`. pdf.js (`pdfjs-dist` 6.3.289, pinned) reads the first 20 pages in a worker thread with a 384 MB heap and 30 s limit (`pdf-thread.mjs`). Issues: **reversed** (visual order: 3 or more common Arabic words that are in the list only backwards and at least twice the forward ones, or 3 words starting with ة), **presentation-forms** (20% or more of the Arabic letters in U+FB50–FDFF and U+FE70–FEFF), **no-unicode-map** (5% or more private-use or replacement characters; or 30% accented Latin letters, the cp1256 reading, in a file linked from an Arabic page that has no Arabic letters), **image-only** (half the pages or more have no text), **no-title** and **no-language** (`/Title` or XMP `dc:title`; `/Lang` or XMP `dc:language`). Each with the fix (export settings in Word and InDesign, embedded fonts with a ToUnicode map, OCR). Moderate for the first four, minor for the last two.
- **Limits:** heuristics; `/Lang` inside a compressed object stream is not seen (a file may carry it); a file that needs a password is "encrypted"; PDFs on other hosts are fetched if their robots.txt allows. Nothing is kept but the numbers, the title and a 12-character example. Tool-only.
- **Depends on:** `pdfjs-dist` (and its optional `@napi-rs/canvas`, pinned to 1.0.9 in `pnpm-workspace.yaml` because 1.0.10 was under the week the workspace requires), the egress rules.
- **Cost:** none.

## 11. AI-training filter test «هل يمر محتواك من فلاتر الذكاء الاصطناعي؟» (rule `ai-training-filters`, tool `ai-training-filter`, `facts.aiTraining`)

- **Decides:** the page's text (visible text outside nav, header, footer and aside, a line for each block) goes through the quality filters of the published FineWeb-2 pipeline for `arb_Arab`, in its order: Gopher repetition (duplicate lines 0.304; top 2, 3, 4-gram 0.197, 0.172, 0.146; duplicated 5 to 10-gram 0.165, 0.153, 0.142, 0.131, 0.12, 0.109), FineWeb quality (lines ending in terminal punctuation at least 0.143, character duplicates at most 0.1, lines per word at most 0.189), Gopher quality (50 to 100,000 words, average word length 2 to 9, symbols, bullets and ellipses, 0.787 of words with a letter, two of the 19 Arabic stop words). Every value is published in `configs/arb_Arab.yml` of huggingface/fineweb-2 at commit `d0defb24f193bb9a5a11b8b14524a03c4858e1b6`, read on 2026-10-04, and `fineweb-2-pipeline.py` of the same commit; what the file does not name (50 words, 0.1 symbol ratio, bullets 0.9, ellipsis 0.3) is datatrove's default at commit `1977fbb0f3c163d43cace334b073dda17fa3ef26` (`gopher_quality_filter.py`, `gopher_repetition_filter.py`, `fineweb_quality_filter.py`), with `PUNCTUATION` and `TERMINAL_PUNCTUATION` copied from its `utils/text.py`. The report gives each check with the measured value, the threshold and pass or fail; a finding for each kind of check that failed. Minor.
- **Differences, said on the card:** language ID is GlotLID in FineWeb-2 and cannot run here, so the language check is a proxy (the share of the text's letters that are Arabic-script, held to the same 0.711) shown as information; words are split by an approximation of spaCy's Arabic tokenizer; the text is the page's visible text, not Trafilatura's output; the C4 filters are not in the FineWeb-2 pipeline ("we do not apply the C4 filters"), so they are shown as a reference. The rule needs 50 words (the pipeline's minimum); a shorter text is "too little text" in the fact.
- **Not run on the site's own pages:** the site self-audit leaves this rule out (`NOT_FOR_SITE_PAGES` in `packages/seo/src/audit/audit.ts`): the rule, glossary and index pages are lists, code and short lines, which the FineWeb-2 filters would drop, rightly, and the rule is for the prose a visitor's site publishes.
- **Depends on:** the text collector. No network.

## 12. Common search misspellings «أخطاء البحث الشائعة» (tool `common-misspellings`, rule `misspellings-uncovered`, behind `ARABLYZER_SUGGEST=1`)

- **Decides:** up to 3 key words of the h1, then the title (generic words such as متجر and موقع skipped) get their common misspellings: ta marbuta/ha, hamza (dropped, put on an initial alef, أ to إ), alef maqsura/ya, a letter dropped (vowels first), two inner letters swapped, and Arabizi (Latin letters, then digits). The likeliest are asked of Google's suggest endpoint, `suggestqueries.google.com/complete/search?client=firefox&hl=ar&q=…`, in all 12 requests at most, shared among the terms, one at a time 0.7 s apart, as ArablyzerBot, cached a day, stopped at the first answer that is not JSON (the response is `["q",["s1","s2",…],[],{…}]`, checked once on 2026-10-04). A form counts as typed when a suggestion equals it or begins with it and a space. Then the page's own words (text, title, description, headings, alt texts) say which typed forms it never writes: a finding for each. Minor.
- **Terms-of-use risk:** the endpoint is not a documented API and Google's terms do not offer it for automated use; it can change or block without notice. So it is off unless the operator sets `ARABLYZER_SUGGEST=1`, volume is small and cached, and the tool page says what is sent. The owner decides whether to turn it on.
- **Limits:** the Arabizi form is made from the consonants (Arabic does not write the vowels), so it rarely matches what people type and is mostly dropped; "typed" says the form exists in queries, not how many.

## 13. AI visibility in Arabic «الظهور في الذكاء الاصطناعي» (tool `ai-visibility`, rule `ai-visibility-gap`, off without keys)

- **Decides:** 3 to 5 Arabic questions are made from the page by fixed templates (best sites for the topic, where to buy, is the brand trustworthy, alternatives to the brand, how to choose; the country is added when §3 names one). Each provider that has a key is asked each question with its web search on; the answer is reduced at once to: the brand (any of its names found by §7) or the domain is mentioned, the domain is among the cited URLs, and the other cited domains. The answer's text is never kept (not in the report, not in the cache). `absent` when none of a provider's answers mentions the site (the competitors it cited are named), `uncited` when it is mentioned and never cited. Minor.
- **Providers and models** (documentation read on 2026-10-04; change the model with `ARABLYZER_<PROVIDER>_MODEL`): OpenAI `gpt-6-luna` on `POST /v1/responses` with `{type: web_search}`; Gemini `gemini-3.8-flash` on `POST /v1beta/interactions` with `{type: google_search}` (the Interactions API takes no output cap we could confirm; the prompt asks for three sentences); Perplexity the Agent API, `POST /v1/agent` with `preset: fast` and `{type: web_search}` (the Sonar chat completions endpoint ended on 2026-09-27, so Sonar as asked is not used); Anthropic `claude-sonnet-5-5` on `POST /v1/messages` with `web_search_20250305`, `max_uses: 2`. Keys go in headers, never in a URL.
- **Cost caps:** at most 5 questions (4 by default) times the providers with a key, never more than 20 requests; at most 600 tokens of answer; 60 s each and 110 s in all; the reduced result is cached 24 hours in memory (a report is kept for at least a day). A refused key (401, 403) or a 429 stops asking that provider; a page on a private address sends nothing.
- **Cost notes (not measured):** every request is paid by the owner. Anthropic's web search is $10 per 1,000 searches, so at most $0.02 a request in searches plus tokens; OpenAI's `gpt-6-luna` is $0.1 and $0.5 per million input and output tokens, plus the web search tool's own fee, which was not read; Gemini and Perplexity prices were not read. Read the first bills before opening the tool to the public.
- **Limits:** answers vary from one run to the next (a snapshot); a brand with a short name (under 4 letters when folded) is matched only by its domain or citation.
- **Tested** with mocked providers only; no key was ever used.

## 14. Chrome UX by country «عدسة كل بلد» (tool `crux-by-country`, rule `crux-country-gaps`, off without credentials)

- **Decides:** the CrUX API has no country dimension; BigQuery's `chrome-ux-report.country_<cc>.<yyyymm>` tables do. One query for the origin (scheme and host of the final page) selects, in each of the nine countries' tables (SA, AE, EG, KW, QA, BH, OM, JO, MA) for the latest month with tables (last month, else the one before), the phone rows, and from the `largest_contentful_paint`, `interaction_to_next_paint` and `layout_instability.cumulative_layout_shift` histograms the share of density in the bins that end at or under 2500 ms, 200 ms and 0.1; a second query asks `experimental.popularity.rank` (if that column differs, only the rank is lost). Both use the named parameter `@origin`, `maximumBytesBilled`, and a free dry run first: a query that would read more than the cap is not run (`too-big` notice). The rule names, for each metric, the countries where fewer than 75% of loads are good. Minor. The column names come from Google's CrUX BigQuery guide (read 2026-10-04) and **have not been run against BigQuery**: the first dry run is the check.
- **Credentials:** `ARABLYZER_BIGQUERY_CREDENTIALS` (a service account's JSON key, or base64 of it) with the role BigQuery Job User, and `ARABLYZER_BIGQUERY_PROJECT` (the project that pays); set both or neither. The key signs a JWT (RS256, scope `bigquery`) that `oauth2.googleapis.com/token` trades for a token (kept until two minutes before it ends); queries go to `bigquery.googleapis.com/bigquery/v2/projects/<project>/queries`, through the egress rules, with no library. `ARABLYZER_BIGQUERY_MAX_BYTES` changes the cap (default 20 GiB).
- **Cost:** not known until the first dry run: the nine tables' columns for origin, form factor and three histograms are read for each query; the card shows the bytes BigQuery billed, and the cap makes the worst case a known number (20 GiB at BigQuery's on-demand price per TiB is the ceiling for a scan; check Google's current price). BigQuery's own cache makes a repeat of the same query free for a day, and so does ours.
- **Limits:** an origin with few visits in a country is not in its table; phones only; the month is the last published.

## Two more ideas, Arabic only

1. **Shaping check in the wild:** compare each Arabic word's drawn width with the same word in a reference font to catch joined letters drawn apart (broken shaping), not only missing glyphs.
2. **Numbers read aloud:** a screen-reader probe for Arabic-Indic digits, currency and dates, to see how a TTS voice speaks the page's prices.
