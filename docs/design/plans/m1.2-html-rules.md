## 1. Why M1.2 is two PRs

The design's M1.2 is about twenty rules plus axe-core, CSS files and font files. The Arabic copy of each rule
waits for the owner, so this part ships the rules that need no browser, and M1.2b the ones that do. Each PR stays
reviewable, and the owner reviews about a dozen rules at a time.

## 2. Rules

| Rule | Category · severity | Fails when |
|---|---|---|
| `title-missing` | onpage · serious | The HTML has no `<title>`, or it is empty |
| `meta-description-missing` | onpage · moderate | No `<meta name="description">` with text |
| `h1-missing` | onpage · moderate | No `<h1>` with text |
| `viewport-missing` | onpage · serious | No `<meta name="viewport">`, or it has no `width=device-width` |
| `og-tags-missing` | onpage · minor | Any of `og:title`, `og:description`, `og:image` is missing or empty |
| `ar-mojibake` | ar-content · serious | Visible text holds Arabic decoded in the wrong encoding: UTF-8 read as Windows-1252 («Ø§Ù„») or Windows-1256 read as Windows-1252 («ÇáÚÑÈíÉ») |
| `ar-digits-mixed` | ar-content · minor | An Arabic page writes numbers in more than one digit set: Arabic-Indic (٠–٩), Persian (۰–۹) and Western (0–9) |
| `ar-tatweel` | ar-content · minor | Arabic words are stretched with tatweel (ـ) between their letters |
| `product-offer-invalid` | schema · moderate | A JSON-LD `Product` has an offer without a price, or with a `priceCurrency` that is not an ISO 4217 code |
| `price-decimals` | commerce · minor | A price in Omani rials, Kuwaiti dinars or Bahraini dinars is shown with one or two decimals, where ISO 4217 gives these currencies three |
| `form-arabic-name-rejected` | forms · serious | A name field's `pattern` rejects an Arabic name |
| `form-arabic-digits-rejected` | forms · moderate | A numeric field's `pattern` rejects Arabic-Indic digits |

**Changed from the design, and why**

- **`h1-missing` instead of `h1-missing-or-multiple`.** Google says several `h1` elements on a page are fine, and
  WCAG asks for none in particular, so "multiple" would be a finding with nothing behind it.
- **`ar-tatweel` instead of `ar-tatweel-overuse`.** A single tatweel inside a word already breaks search and
  copying («مـحـمـد» does not match «محمد»), so there is no threshold to call "overuse".
- **`form-phone-direction` moves to M1.2b.** Many sites set a phone field's direction in CSS, which the HTML does not
  show; only the rendered page knows. `form-label-missing` moves too: axe-core answers it.

## 3. New facts (`collectors`)

- `html.headings`: every `h1`–`h6` with its level, text and location.
- `html.fields`: every `input`, `textarea` and `select` with type, name, id, autocomplete, inputmode, pattern,
  placeholder, dir and the text of its label, so the form rules can tell a name field from a phone field.
- Nothing new for JSON-LD: `html.scripts` already carries each block's text and location.

## 4. How the rules decide

- **Name fields:** `autocomplete` is `name`, `given-name`, `family-name` or `nickname`, or the field's name, id,
  label or placeholder names a name («الاسم», `name`, `first_name`…), and it is not an email, phone or number
  field. Test values: «محمد العبري», «فاطمة», «عبد الله». The field fails when its pattern compiles with the `v`
  flag and rejects any of them.
- **Numeric fields:** `inputmode` `numeric` or `decimal`, `type="tel"`, `autocomplete` `tel` or a postal code, or
  a pattern made only of digit classes. Test values: the pattern's own example written with Arabic-Indic digits,
  from a Western-digit value the pattern accepts, when one of a few candidates (8 to 12 digits, with and without a
  leading `+`) matches. No accepted Western value, no finding: we only compare like with like. `type="number"` is
  left out: browsers convert what a keyboard types there, which setting a value in script cannot show.
- **Mojibake:** runs of the characters that UTF-8 Arabic turns into when read as Windows-1252 or Latin-1 (`Ø` and
  `Ù` followed by a character in 0x80–0xBF), and the Windows-1252 letters that Windows-1256 Arabic turns into
  (`Ç`, `á`, `Ú`, `Ñ`, `È`, `í`, `É`…), counted only in runs of at least four and only when re-encoding the run
  gives valid Arabic text. That second check keeps French and Spanish words out.
- **Digits:** counted in the visible text of Arabic pages; the finding shows the first example of each set.
- **Prices:** a number next to a currency marker for OMR, KWD or BHD: the ISO code, the Arabic abbreviation («ر.ع.»،
  «د.ك.»، «د.ب.») or the currency's Arabic name, and «RO», «KD», «BD» when they touch the number. Western and
  Arabic-Indic digits, with `.` or «٫» as the decimal mark.
- **Products:** every JSON-LD block that parses, `@graph` included; `Product` and its subtypes by `@type`;
  `offers` as an object or array, `AggregateOffer` with `lowPrice` counting as a price.

## 5. Tests

- Each rule: wrong and right fixtures, a detector test on facts, Arabic and English copy with every section.
- The fixture matrix of the rules and engine packages: each wrong fixture fails its own rule alone, each right
  fixture passes every rule.
- Collectors: headings and fields, with locations, including forms inside `template` (left out, as the parser
  keeps them inert) and fields outside any form.

## 6. Commits

Plan → fixtures get a description and Open Graph tags → collectors (headings, fields) → one commit per rule (wrong
fixture, right fixture, detector, copy) → README and record.

## 7. For the owner

- The Arabic copy of the twelve rules, on a review page, as before.

|---|---|

**Changes from the plan, and why**

- **`product-offer-invalid` reads an offer given by `@id` from every object on the page with that `@id`**, in any
  block, since JSON-LD makes them one object; an `@id` nothing on the page defines is skipped. Findings point at the
  line of the value through its JSON Pointer (`lib/json-positions.ts`). The walk stops at 50,000 objects and 64
  levels. An `AggregateOffer` needs `lowPrice`, as Google asks; a price of 0 passes, as product snippets allow.
- **`price-decimals` reports once per currency per page**, at the first price, with the number of such prices: the
  cause is one price format, not each price. A number and its currency split across inline elements
  (`<bdi>12.50&nbsp;<span>ر.ع.</span></bdi>`) are read together. «ريال» or «دينار» alone does not count, and
  numbers whose separators do not show the decimal mark («12,50») pass.
- **The form rules run a page's patterns in a `node:vm` context with a 50 ms limit**, each pattern once per page,
  and stop after three slow ones: a pattern such as `(a*)*b` could otherwise hold a scan for minutes. The page's
  text is only ever data to `new RegExp`.
- **`form-arabic-name-rejected` compares names of the same shape** (length and number of words): a pattern that
  refuses every two-word name, or every four-letter one, is not about Arabic. So `[A-Za-z ]+` fails on
  «محمد العبري» against «Omar Alabri», and `[ا-ي]+` fails on «أحمد» against «محمد», while `\p{L}+`, which refuses
  spaces, does not fail. Names asked for in English or as in the passport, user names, and card, company and bank
  names are left out.
- **`form-arabic-digits-rejected` builds its example from the placeholder** («9xxxxxxx» gives 91234567), then from
  common lengths and the digits the pattern spells out («05», «+968»), and fails only when the field takes none of
  those numbers in Arabic-Indic digits: a pattern that takes them for the local number is not faulted for its
  country code.
- **Both form rules read Arabic pages only** (`<html lang>` Arabic, or mostly Arabic text): on an English page,
  asking for Latin letters is a choice, not a fault.
- **The self-audit found our own tool pages had no Open Graph tags.** They now carry `og:type`, `og:site_name`,
  `og:title`, `og:description` and `og:url`. `og:image` waits for the site build, which makes an image for every
  page (BUILD-PLAN §6.5): the audit lets that one finding through by name, with the reason, and fails on any other.
- **Our WhatsApp tool page wrote «٩٦٨» as plain text next to Western digits**, which `ar-digits-mixed` reports; as an
  example of what not to type it is now code. The owner reviewed that copy; its wording is unchanged.
- **Node decodes `windows-1252` as ISO-8859-1** for 0x80–0x9F, where browsers use the WHATWG table (€, ‘ ’, “ ”…).
  The collectors now decode it as browsers do, and `ar-mojibake` builds its table from the same decoder.
- **Unicode escapes in source.** Character classes of harakat, directional marks and a BOM were literal characters;
  they are escapes now, so nothing in the code is invisible.
- Ruleset 0.3.0.
