# M6.1 Tools batch 1: stores first, then crawl and quick wins — Implementation Plan

> **ملخص للمالك:** الدفعة الأولى من المرحلة 6 (الوصول إلى ~110 أداة، خطة البناء §17). **أدوات المتاجر** (ميزتنا عند تجار سلة وزد وشوبيفاي): فحص ملف المنتجات لـ Google Merchant (XML أو TSV: الحقول المطلوبة، السعر والعملة وتوفّر المنتج بصيغ Google، رقم GTIN، جودة العناوين العربية) وفحص الملف نفسه، وفحص بيانات المنتج المنظّمة (السعر والعملة والتقييم والتوفّر)، وفحص hreflang للمتاجر، وفحص نموذج الدفع بالعربية، ورسالة واتساب الجاهزة، وصفحات السياسات (الخصوصية والشروط والاسترجاع والشحن)، وبيانات النشاط المحلي. ثم **الزحف والوصول** (الصفحة الوهمية 404، معاملات الروابط، الترقيم، تواريخ التحديث) ثم **مكاسب سريعة** (صورة المشاركة، النص البديل، نص الروابط، روابط الاتصال، مسار التنقّل، الواجهة المتجاوبة، الترميز، الضغط، الاسم التجاري، قابلية قراءة الذكاء الاصطناعي). النصوص العربية كلها `reviewed: false`. **المطلوب منك:** مراجعة النصوص، وإن أردت صفحات التقارير الذهبية تُولَّد من CI فقط.

**Goal:** about twenty more tools, each a rule or two plus a page, with no new service: what the page, its headers and its one file already give.

Design source: `m5.3-search-tools.md` (conventions, record style), `m2.3-more-tools.md` (kinds of tool), BUILD-PLAN §5.1 and §17, R7/R8 design rules.

## 0. Measured before planning (2026-10-11)

| Question | Result |
|---|---|
| How is a tool registered? | `packages/tools/src/tools/<slug>/{tool.ts,copy.ar.md,copy.en.md}` and `registry.ts`; the web reads the registry (no per-tool code for a `scan` tool). A rule is `packages/rules/src/rules/<id>/{rule.ts,rule.test.ts,copy.*.md,example.md,fixtures/{wrong,right}}` and `index.ts`. |
| What does a fixture have to satisfy? | `fixtures.test.ts`: every wrong fixture fails its own rule alone, every right fixture passes every rule. So a new rule must not fire on the 79 rules' existing fixtures: new rules are narrow (they apply only when the page shows the thing: a feed, a store platform, hreflang links, a WhatsApp text, a product in JSON-LD). |
| Golden pages | `golden-coverage.test.ts`: between them the pages fail and pass every rule (except tool-only ones). Pages 37 (wrong) and 38 (right), a store, are added; the reports come from CI's `golden-actual`. |
| A product feed | Not a page: `scan()` fetches the address the visitor gives and `collectPage` reads HTML only. A feed is XML or tab-separated text, so a new collector `feed` reads the response body (RSS 2.0 or Atom 1.0 with the `g:` namespace, or TSV). Like the site's search, it is for a tool's scan alone (`TOOL_ONLY`): a whole scan of a page never asks it. |
| Anchors | `AnchorElement` has no text. It gains `text`, `rel` and `ariaLabel` (own walk budget). |

## 2. Contracts

- **`feed` collector** (`packages/collectors/src/feed.ts`): `collectFeed({body, contentType})` → `FeedFacts`, either `{kind:'feed', format:'rss'|'atom'|'tsv', items, total, truncated}` (an item is its attributes by Google's names, `g:` and spaces folded: `image_link`, `sale_price`; at most 5,000 items kept, the rest counted) or `{kind:'unreadable', reason}` (`html`, `empty`, `compressed`, `not-utf8`, `not-xml`, `not-a-feed`, `no-items`, `no-columns`). XML is read with `sax` under the sitemap reader's limits (depth 32, 256 attributes). Required of the page: a 2xx answer. The engine makes it only when a rule that needs `feed` runs; a scan that names such a rule is the only one that does (`TOOL_ONLY`).
- **Honest limits, said by the copy:** 5,000 items (notice `feed-partial`), no `.gz` feed, no variants/"item_group_id" completeness, nothing fetched but the feed itself (image and product URLs are not requested), Google's required attributes are the ones its specification lists for every country, not per-country extras (tax, shipping).
- **Rules read what is there**: no network of their own; `appliesTo` is narrow so the rest of the rule set and every existing fixture are unchanged.

## 5. As built (2026-10-11)

- **Counts.** 22 tools (57 → 79) and 23 rules (79 → 102); `RULESET_VERSION` 0.10.0. Tests added: collectors 19 (feed, anchors), rules about 270, one engine file for the feed in a scan (4), the web tag tests. The site audit reads 530 pages with no problem.
- **Where it differs from the plan above.**
  - `checkout-form-check` became **`arabic-checkout-test`**: the platform fingerprints of webappanalyzer match a URL with `/checkout` as "Cart Functionality", and the self-audit's `platform-detected` flagged our own page.
  - `compression-check` was dropped for **`carousel-direction-check`** (the rule `rtl-icon-role` had no tool): `text-compression-missing` differs between its wrong and right fixtures only in a response header, so no honest wrong/right example exists for its tool page.
  - `soft-404-signals` is in `SERVER_RESPONSE_RULES`: the self-audit reads a built 404 page as status 200, and it must not call it a soft 404; on the live site the server answers 404. `og-image-invalid` leaves an empty tag to `og-tags-missing`.
  - `form-autocomplete-missing` does not flag an explicit `autocomplete="off"` (the field may be for someone else's details); `policy-pages-missing` takes a cart/checkout link or a store platform as a store.
  - `hreflang-*` rules find the page itself by its canonical address, and do not judge a page none of whose links is on its host (staging, proxy). Return links need a crawl and are not checked; the copy says so.
- **Existing fixtures completed** so every right fixture passes every rule: `autocomplete` on the email/phone/name fields of four form fixtures and golden 07; a policy footer on the fixtures with a cart link and on `platform-detected`'s; `x-default` on the `hreflang-invalid-code` wrong fixture; an image on golden 01 and 03.
- **Golden pages** 37 (store, wrong), 38 (store, right), 39 (a "not found" page that answers 200 and a page of a list, wrong) and 40 (right); `golden-coverage` expects 35 reports. The reports come from CI's `golden-actual`.
- **Not done, on purpose.** The store speed profile (script weight by technology): the browser report has no size per script; it is a change to the three-engine suites, which this batch kept out. No live Salla/Zid feed was read; the feed rules are checked against Google's specification and stand-in feeds. `bulk-status`, `sitemap-lastmod-check`, `hreflang-sitemap-check`, the platform store checks and the generators are the next batch.
