# M1.1 Browser Foundation — Implementation Plan

> **ملخص للمالك:** هذه خطة أول PR في المرحلة 1 (M1.1) حسب `docs/design/phase-1.md`: بروكسي خروج للمتصفح يطبّق
> قواعد المنع نفسها على كل طلب، وحزمة `browser` تشغّل Playwright خلفه، وخيارات `--render` و`--engines`
> و`--screenshots` في الـ CLI، وأول قواعد العرض العربي والاتجاه. اختبارات SSRF للمتصفح تعمل في الـ CI على المحرّكات
> الثلاثة. الكود هو المرجع النهائي؛ هذه الوثيقة سجلّ للقرارات. اعتمد المالك النص العربي للقواعد الخمس الجديدة في
> 2026-09-26 («النصوص تمام»). وكما قرر تصميم المرحلة 1، صار WebKit لا يعمل إلا داخل حاوية شبكتها معزولة، لأن WebRTC
> فيه يتجاوز البروكسي (التفاصيل في السجلّ آخر الوثيقة).

**Goal:** `pnpm arablyzer <url> --render` renders the page in Chromium (and Firefox and WebKit with `--engines`)
behind a proxy that vets every request the way `safeFetch` does; CI shows that a hostile page reaches no local
address by any route the browser offers; the first ar-render and rtl rules run on the rendered page.

**Branch:** `phase-1/browser`, stacked on `phase-0/tools-seo` (PR #3), with its own PR.

## 1. Packages

| `collectors` | The `RenderedFacts` types |
| `rules` | `needs: 'render'`, `Evidence.rendered`; the first ar-render and rtl rules |
| `engine` | The render step with the §11 time budget; render notices |
| `report-schema` | 0.2.0 (section 6) |
| `cli` | `--render`, `--engines`, `--screenshots` |

## 2. The proxy

- Listens on `127.0.0.1`, port 0, with a user name and a random password for each render; a request without them
  gets 407.
- Takes absolute-form HTTP requests and CONNECT only; an origin-form request (something talking to it as a web
  server) is refused.
- Every request goes through `checkUrl` and `resolveEndpoint` with the scan's policy and resolver, then connects
  to an address it vetted, as `safeFetch` does, so DNS cannot move a request after the check. Refusals carry the
  `safeFetch` error codes and go to a bounded log.
- The proxy follows no redirects: the browser follows them, and every hop is a new request, vetted again.
- Hop-by-hop headers are dropped; `Proxy-Authorization` is never forwarded.
- Limits per engine (§11): 300 requests and 25 MB from the network; past them, new requests are refused and the
  log says so.
- `--allow-private` keeps the rule of `safeFetch`: when the page itself is public, private addresses stay closed
  for every request the page makes. The engine hands the proxy the policy the page fetch ended with.

## 3. The browser

- `renderPage(url, options)` renders in each requested engine, one after the other (one browser at a time,
  §18.3.1), each with a new browser, context and proxy.
- **Chromium:** headless shell; proxy bypass `<-loopback>`; both WebRTC flags; `--disable-quic`;
  `--dns-prefetch-disable`; background networking off.
- **Firefox:** `network.proxy.allow_hijacking_localhost`, `media.peerconnection.enabled` false, HTTP/3 off, DNS
  prefetch and the predictor off.
- **WebKit:** renders only where the network is isolated (`ARABLYZER_NETWORK_ISOLATED=1`), because its WebRTC
  goes around the proxy (Record). Elsewhere its run is refused before any browser or proxy starts.
- **Context:** service workers blocked, downloads refused, viewport 390 × 844 CSS px at device scale 2, locale
  `ar`, time zone `Asia/Riyadh`, reduced motion, light colour scheme. The viewport meta is not applied, because
  Playwright cannot apply it in Firefox, so the overflow rule only runs on pages that declare
  `width=device-width`.
- **Identity:** the engine's own user agent with `ArablyzerBot/1.0 (+https://arablyzer.com/bot)` added. No
  clicks, no typing, no form submission (§13); dialogs are dismissed and pop-ups closed.
- **Waiting:** the `load` event, then `document.fonts.ready` and 500 ms without network requests, both within a
  fixed cap. Finite animations are finished and endless ones cancelled before measuring, as Playwright does for
  screenshots.
- **Measuring:** one script in the page, bounded in element count and time, plus CDP for used fonts in Chromium.
  Node validates and bounds what comes back. The script runs in the page's own JavaScript world, so a page can
  falsify its own measurements; it can only make its own report wrong.
- **Screenshots:** the first screen, PNG, only when asked for.

## 4. Rendered facts (per engine)

- Engine, version, status, final URL, the document's HTTP status, duration.
- The root's computed `dir` and `lang`; the document's scroll width and the viewport width.
- Elements that reach past the viewport (the first 20 in document order): selector and box.
- Text blocks with Arabic letters (bounded): selector, box, `letter-spacing`, whether it changed the text's width,
  the first font family and its FontFace status, and in Chromium the fonts that drew the text.
- Numbers and Latin words inside RTL text whose characters are drawn out of order (the first 20): selector, text
  and box.
- Requests: total, and refused by reason.

## 5. Rules

| Rule | Category · severity | Fails when | Engines |
|---|---|---|---|
| `ar-letter-spacing` | ar-render · moderate | Arabic text has `letter-spacing`, and an engine applied it, or WebKit did not render the page (Record) | all |
| `ar-font-fallback` | ar-render · moderate | The web font set for Arabic text did not load, so the text shows in another font | all |
| `ar-font-no-arabic` | ar-render · moderate | The web font loaded but has no Arabic letters, so they come from another font | Chromium |
| `rtl-bidi-isolation` | rtl · serious | A number or a Latin word in RTL text is drawn out of order (a phone number's groups, `C++`) | all |
| `rtl-horizontal-overflow` | rtl · serious | The page is wider than a phone screen, so it scrolls sideways | all |

Each follows the rule contract of Phase 0: a wrong fixture, a right fixture, a pure detector tested on facts,
browser tests on the fixtures in every available engine, and Arabic and English copy. Severities are final once
the copy explains them.

**Moved, and why**

- `ar-shaping-broken`: no deterministic way to tell broken joins from the rendered page yet. The engines' output
  is pixels; the rendering lab's screenshots come first, and the rule waits for a method that tests can pin down.
- `rtl-physical-css`: needs the page's CSS files read and parsed, which M1.2 adds for fonts; it moves there.
- `rtl-mirrored-icons`: it recognises icons by the class names of icon libraries, which needs fixtures for each
  library; it moves to M1.2, so this PR stays on the browser foundation.

## 6. Report schema 0.2.0

- `scan.render`: for each engine, its name, version, status, duration and request counts.
- `evidence.engines` and `evidence.box` for findings from the rendered page.
- Notices: rendering failed or timed out, engine not installed, request limit reached, browser rules not run.
- 0.2.0 stays open until Phase 1 ends: nothing is published, and M1.2 and M1.3 add the score and the new facts to
  it.

## 7. CLI

- `--render` renders in Chromium. `--engines chromium,firefox,webkit` (or `all`) and `--screenshots <dir>` imply
  it; screenshots are written as `<dir>/<engine>.png`.
- Without `--render`, rules that need the browser are left out and a notice says so; naming one in `--rules`
  without `--render` is a usage error.
- A missing browser exits with code 2 and the command that installs it.

## 8. Tests and CI

- **Proxy SSRF tests (no browser):** every address class `safeFetch` refuses, through both request forms;
  answers that mix public and private addresses; rebinding; ports; CONNECT; credentials; origin-form requests;
  the limits.
- **Browser SSRF suite, per engine:** a hostile page tries `img`, `iframe`, `fetch`, XHR, WebSocket, EventSource,
  `sendBeacon`, CSS `@import` and `url()`, prefetch and preload, meta refresh, redirects, a worker's `fetch`,
  WebRTC (STUN and TURN, UDP and TCP) and pop-ups, towards a loopback port that is not allowed (TCP and UDP),
  `169.254.169.254`, `[::1]`, `localhost` and a name that resolves to loopback. It passes when the local target
  receives nothing and the proxy log shows each refusal.
- **Rules:** pure detector tests on facts in the unit suite; fixture tests in the browser suite.
- **CI:** a new job installs the three browsers (cached by Playwright version) and runs `test:browser` with
  `ARABLYZER_REQUIRE_ENGINES=chromium,firefox,webkit`, so a missing engine fails instead of being skipped.
  Locally, `ARABLYZER_CHROMIUM_PATH` points at an installed Chromium.

## 9. Risks

- **WebKit and the proxy** are untested until CI runs the suite. If any request goes around the proxy,
  `--engines webkit` refuses to run outside a network-isolated container and says why. *(It did; see the Record.)*
- **Engine versions:** this environment has Chromium 141 and CI has 153; where measurements differ, CI is the
  reference.
- **Fonts:** the rules here ask whether the declared web font drew the text, not which fallback did, so they do
  not depend on the machine's fonts.
- **Memory:** one browser at a time, closed after each engine.

## 10. Commits

docs plan → egress proxy (tests first) → browser package and its SSRF suite → rendered facts → report schema
0.2.0 → engine render step → CLI flags → one commit per rule (wrong fixture, right fixture, detector, copy) → CI
job → docs.

**Measured in CI** (Playwright 1.63: Chromium 153, Firefox 155, WebKit 26.6)

| Question | Result |
|---|---|
| WebKit and the proxy | Run 36269856352: the hostile page's WebRTC reached the loopback trap, 3 UDP packets and 1 TCP connection; every other route went to the proxy. Playwright's WebKit turns WebRTC on for every page it drives, and its protocol has no setting that turns it off. |
| A page that holds its main thread, 4 s budget | WebKit took 34.0 s, closing the browser. Browsers are now killed when their page runs out of time: 4.02 s in all three engines. |
| WebTransport | Without a proxy, Chromium 141 sent QUIC to a local UDP port even with `--disable-quic`; behind the proxy, no engine sent anything. |
| `letter-spacing` on Arabic | Chromium 153 and Firefox 155 left it out; WebKit 26.6 drew it between the letters. |
| The hostile SSRF page | Chromium 2.8 s, Firefox 4.8 s, WebKit 9.6 s |
| CLI end to end (here, Chromium 141) | 1.4 s for a small page. A 5 s wait that nothing cleared kept the process alive 4.5 s after the report; it no longer does. |

**Changes from the plan, and why**

- **WebKit runs only where the network is isolated**, as section 9 said it would if anything went around the proxy.
  `renderPage` refuses it (status `refused`, a new value in schema 0.2.0) unless `ARABLYZER_NETWORK_ISOLATED=1`; the
  CLI makes `--engines webkit` a usage error that says why, and `--engines all` means Chromium and Firefox there. The
  SSRF suite runs the hostile page without WebRTC for WebKit, and a separate test shows the leak still happens, so we
  learn when it stops.
- **Browsers launch as Playwright browser servers** (on loopback, at an unguessable path), because only a server can be
  killed: at once when the page ran out of time, or after 5 s of trying to close it.
- **The SSRF suite also tries WebTransport**, and Firefox gets `network.webtransport.enabled=false`. The trap names what
  reached it (STUN, or the first line of a request) and closes connections a client keeps open.
- **`ar-letter-spacing` also fails when no engine drew the spacing but WebKit did not render the page.** A default
  scan renders in Chromium only, which never draws it, so the planned condition would never fire there, while Safari,
  on WebKit, does draw it.
- **`appliesTo` gets the evidence**, so a render rule decides from the rendered page, whose text may come from scripts.
- **A scan that does not render in Chromium leaves out `ar-font-no-arabic`** with a notice naming the engine, instead
  of reporting it as an error and making every such scan partial; named with `--rules`, it is a usage error.
- **A scan whose engines did not all render is partial**, so a missing browser exits 2 as section 7 says, whatever the
  rules.
- **`rtl-bidi-isolation` puts the number or word in the snippet**, which reports show left to right: inside the
  message, right-to-left text would draw it out of order again.
- **`rtl-horizontal-overflow` holds only right-to-left pages** with `width=device-width` to the phone's width.
- Ruleset 0.2.0. New notices: `engine-refused`, `render-engine-skipped`.
