## 0. Measured before planning (2026-09-27, the owner's Mac)

| Question | Result |
|---|---|
| Stylesheet and font bodies during a render | With every request routed as the render does, Chromium 153 and Firefox 155 hand over the whole body of each stylesheet and font file (`response.body()`): the test's 20,020-byte WOFF2 arrived whole. So nothing is fetched twice |
| Reading a font's `cmap` ourselves | A short reader (TTF/OTF, WOFF with `zlib`, WOFF2 with Node's built-in Brotli, `maxOutputLength` bounded) gives the same 510 code points as fontTools, 165 of them Arabic, for the test font as TTF, WOFF and WOFF2, in 0.6–1.8 ms. fontkit 2.0.4, planned in M1.2, pulls in nine packages, a JavaScript Brotli among them, to read far more than we need; the reader replaces it |
| Reading a body whose size is unknown | `response.body()` hands over the decoded body: a 65 KB gzip stylesheet or font came back as 64 MB in Chromium 153, Firefox 155 and WebKit 26.6 (WebKit evicted the stylesheet), and our process grew by 133–313 MB. The proxy counts bytes on the wire only. Asking for `Accept-Encoding: identity` is ignored by Chromium and WebKit. So a body is read only when its decoded size is known and under the cap: from `request.sizes()` when the response has no `Content-Encoding`, else from Resource Timing's `decodedBodySize`, read through getters kept by an init script before the page's scripts run. Google Fonts sends `Timing-Allow-Origin: *` for its CSS and font files. Firefox 155 and WebKit 26.6, following Fetch, give no size for another origin's stylesheet linked without `crossorigin` (an opaque response), even with that header; Chromium 153 gives it. A body of unknown size is not read, and what depends on it is left undecided |
| css-tree 3.2.1 (MIT) on page CSS | 1 MB, 48,000 declarations: 73 ms. Hostile shapes: 20,000 nested `@media`, a 2 MB string, 780 KB of `{`, 100,000 unclosed blocks: 8–16 ms each |

## 1. Rules

| Rule | Category · severity | Fails when |
|---|---|---|
| `ar-font-missing-letters` | ar-render · moderate | The web font set for Arabic text lacks characters that text uses (such as «ڤ», «پ» or «٠»), so the browser draws them in another font |
| `rtl-physical-css` | rtl · info | A right-to-left page's CSS positions with physical sides (`margin-left`, `padding-right`, `left`, `float: right`, `text-align: left`…) rather than logical ones (`margin-inline-start`…) |
| `rtl-mirrored-icons` | rtl · needs review | A right-to-left page shows direction icons (arrows, chevrons) as drawn for left-to-right text: `fa-arrow-right`, `chevron_right`, «→»… |

## 2. How the rules decide

- **Font files:** the render keeps the bodies of font files (at most 20, 5 MB each) and stylesheets (at most 30,
  2 MB each, 10 MB in all). The stylesheets' `@font-face` rules tie each file to its family and `unicode-range`.
  A file's coverage is its `cmap`, within its `unicode-range`.
- **Missing letters:** for each Arabic text block whose first family is a web font, the characters of its text
  that the family's files do not cover. A family without any Arabic letter is left to `ar-font-no-arabic`.
- **Physical CSS:** declarations with physical sides in the page's stylesheets and `<style>` elements, on
  right-to-left pages, counted with the first examples. Rules scoped to a right-to-left page (`[dir="rtl"]`,
  `:dir(rtl)`) are left out: they are written for this direction on purpose. Info: never deducted.
- **Mirrored icons:** elements whose classes name a direction icon of Font Awesome, Bootstrap Icons, Material
  Icons and Symbols, or Lucide, and Unicode arrows that do not mirror (→ ←; ‹ › « » mirror by themselves), on
  right-to-left pages, with no horizontal flip in their computed transform. A right arrow may be right in a
  right-to-left page ("back"), so a person decides: needs review, never deducted.

## 3. Facts (`collectors`, `browser`)

- `RenderedFacts.fontFiles`: each font file's URL, the families and ranges that use it, and its coverage as
  code point ranges; `null` coverage when the file could not be read.
- `RenderedFacts.css`: the physical-side declarations (the first 20, with selector, property and value, and the
  count), from stylesheets and `<style>` elements.
- `RenderedFacts.directionIcons`: direction icons with their selector, what names them (a class or a character)
  and whether they are flipped.
- The `cmap` reader and the CSS reading are pure functions in `collectors`, tested on files.

## 4. Tests

- The `cmap` reader on the test font as TTF, WOFF and WOFF2, and on broken, truncated and oversized files.
- Each rule: wrong and right fixtures in every engine, a detector test on facts, Arabic and English copy.

## 5. For the owner

- The Arabic copy of the three rules, on a review page.

Playwright 1.63 (Chromium 153, Firefox 155; WebKit never runs on macOS, CI renders it):

|---|---|

| Unit and rule tests (`pnpm test:unit`) | 1,295: rules 721, engine 145, seo 116, collectors 111, tools 53, report-schema 41, browser 39, cli 35, egress 23, fixtures 11 |
| E2E (`pnpm test:e2e`) | 113 |

| SEO self-audit (`pnpm seo:audit`) | 8 pages, no problems |

The render matrix renders every render rule's fixtures in every engine and runs all 38 rules on each. The overflow
rule's wrong fixture, a drawer placed with `left: -280px`, also fails `rtl-physical-css`: that `left` is its fault.

**Changes from the plan, and why**

- **No fontkit** (§0): a reader of the `cmap` table alone. It reads what fontTools reads from the test fonts as
  TTF, WOFF and WOFF2, and from a font whose table looks glyphs up through `idRangeOffset`.
- **A body is read only at a size known beforehand** (§0). Resource Timing names sizes by URL, so a size counts
  only for a URL that came back once, in any frame and of any kind, with one timing entry: a page could otherwise
  load a URL twice and keep the second load out of Resource Timing. A request still arriving is not waited for.
- **`ar-font-missing-letters` counts only device fonts as "another font".** A later web font in the list that has
  the character was chosen by the site; a font that lacks any of the 28 letters is `ar-font-no-arabic`'s; format
  and unassigned characters are left out in Node, so each engine's characters are judged by one Unicode version.
- **`rtl-physical-css` reports each stylesheet once**, with its count and first declaration. Besides rules written
  for one direction or language, it leaves out blocks that set their own `direction`, opposite properties set
  alike (`left: 0; right: 0`), `@keyframes`, and files named for right-to-left pages (`style-rtl.css`).
- **`rtl-mirrored-icons` looks for what points right or forward**: icon-font classes, Material names, and arrows
  in Arabic text or alone in an inline element beside it. A transform that mirrors an icon (on it, its
  `::before` or `::after`, or three ancestors) leaves it out.
- **css-tree's parser and walker alone.** Its main entry brings the lexer, which loads JSON data at run time, and
  the CLI's single-file bundle failed at startup; the two entries need no data (142 KB bundled).

**Google Fonts, rendered once (a local page with Cairo, Chromium and Firefox)**

In Chromium Google's stylesheet was read, compressed and from another origin, and each `unicode-range` part of
Cairo joined to its file: «ڤ» «پ» «چ» «گ» and the Arabic-Indic digits are in it, so nothing is reported. Firefox
gives no size for Google's stylesheet, and WebKit none for another origin's (§0), so there Cairo's Arabic range
stays unknown and the rule says nothing.

## Review (2026-09-27)

An independent review read the diff and ran the tests and probes. It found no path that reads a body of
unbounded size, and no way for a page to make `ar-font-missing-letters` report a character it cannot vouch
for: every uncertainty ends in "unknown". Each finding was reproduced before its fix.

| # | Finding | Fix |
|---|---|---|
| 1 | The `cmap` reader's `idRangeOffset` path was untested: the test fonts map by `idDelta` alone | A font made with fontTools' FontBuilder, 73 characters mapped to glyphs in shuffled order, reads as fontTools reads it; synthetic tables cover glyph 0 in the array, `idDelta` after the lookup, and an array shorter than its segment |
| 2 | Leaving out unassigned characters (`\p{Cn}`) in the page used each engine's Unicode version, so engines could judge the same text differently | The page script keeps every character of the Arabic blocks; the rule leaves out format and unassigned ones in Node |
| 3 | Format 4 segments out of order were read in part, which could report a letter as missing | Segments out of order or overlapping make the table malformed, as they make browsers refuse the font (OTS) |
| 4 | The schema for the page's `<style>` texts bounded their number, not their length | Each is bounded too |

Also added after the review: Tailwind CSS's logical classes (`ms-4`, `start-0`, `text-start`…) in
`rtl-physical-css`'s fix, since the owner's sites use Tailwind.
