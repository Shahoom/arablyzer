## 0. Measured before planning (2026-09-27, the owner's Mac)

| Question | Result |
|---|---|
| Stylesheet and font bodies during a render | With every request routed as the render does, Chromium 153 and Firefox 155 hand over the whole body of each stylesheet and font file (`response.body()`): the test's 20,020-byte WOFF2 arrived whole. So nothing is fetched twice |
| Reading a font's `cmap` ourselves | A short reader (TTF/OTF, WOFF with `zlib`, WOFF2 with Node's built-in Brotli, `maxOutputLength` bounded) gives the same 510 code points as fontTools, 165 of them Arabic, for the test font as TTF, WOFF and WOFF2, in 0.6–1.8 ms. fontkit 2.0.4, planned in M1.2, pulls in nine packages, a JavaScript Brotli among them, to read far more than we need; the reader replaces it |
| Reading a body whose size is unknown | `response.body()` hands over the decoded body: a 65 KB gzip stylesheet or font came back as 64 MB in Chromium 153, Firefox 155 and WebKit 26.6 (WebKit evicted the stylesheet), and our process grew by 133–313 MB. The proxy counts bytes on the wire only. Asking for `Accept-Encoding: identity` is ignored by Chromium and WebKit. So a body is read only when its decoded size is known and under the cap: from `request.sizes()` when the response has no `Content-Encoding`, else from Resource Timing's `decodedBodySize`, read through getters kept by an init script before the page's scripts run. Google Fonts sends `Timing-Allow-Origin: *` for its CSS and font files. A body of unknown size is not read, and what depends on it is left undecided |
| css-tree 3.2.1 (MIT) on page CSS | 1 MB, 48,000 declarations: 73 ms. Hostile shapes: 20,000 nested `@media`, a 2 MB string, 780 KB of `{`, 100,000 unclosed blocks: 8–16 ms each |

## 1. Rules

| Rule | Category · severity | Fails when |
|---|---|---|
| `ar-font-missing-letters` | ar-render · moderate | The web font set for Arabic text lacks characters that text uses (such as «ڤ», «پ» or «٠»), so the browser draws them in another font |
| `rtl-physical-css` | rtl · info | A right-to-left page's CSS positions with physical sides (`margin-left`, `padding-right`, `left`, `float: right`, `text-align: left`…) rather than logical ones (`margin-inline-start`…) |
| `rtl-mirrored-icons` | rtl · needs review | A right-to-left page shows direction icons (arrows, chevrons) as drawn for left-to-right text: `fa-arrow-right`, `chevron_right`, «→»… |

## 2. How the rules decide

- **Font files:** the render keeps the bodies of font files (at most 20, 5 MB each) and stylesheets (at most 30,
  2 MB each, 10 MB in all). The stylesheets' `@font-face` rules tie each file to its family and `unicode-range`.
  A file's coverage is its `cmap`, within its `unicode-range`.
- **Missing letters:** for each Arabic text block whose first family is a web font, the characters of its text
  that the family's files do not cover. A family without any Arabic letter is left to `ar-font-no-arabic`.
- **Physical CSS:** declarations with physical sides in the page's stylesheets and `<style>` elements, on
  right-to-left pages, counted with the first examples. Rules scoped to a right-to-left page (`[dir="rtl"]`,
  `:dir(rtl)`) are left out: they are written for this direction on purpose. Info: never deducted.
- **Mirrored icons:** elements whose classes name a direction icon of Font Awesome, Bootstrap Icons, Material
  Icons and Symbols, or Lucide, and Unicode arrows that do not mirror (→ ←; ‹ › « » mirror by themselves), on
  right-to-left pages, with no horizontal flip in their computed transform. A right arrow may be right in a
  right-to-left page ("back"), so a person decides: needs review, never deducted.

## 3. Facts (`collectors`, `browser`)

- `RenderedFacts.fontFiles`: each font file's URL, the families and ranges that use it, and its coverage as
  code point ranges; `null` coverage when the file could not be read.
- `RenderedFacts.css`: the physical-side declarations (the first 20, with selector, property and value, and the
  count), from stylesheets and `<style>` elements.
- `RenderedFacts.directionIcons`: direction icons with their selector, what names them (a class or a character)
  and whether they are flipped.
- The `cmap` reader and the CSS reading are pure functions in `collectors`, tested on files.

## 4. Tests

- The `cmap` reader on the test font as TTF, WOFF and WOFF2, and on broken, truncated and oversized files.
- Each rule: wrong and right fixtures in every engine, a detector test on facts, Arabic and English copy.
