## 2. Decisions

- **All seven writing tools are client-side**, on `TextTool` (M10.1): nothing typed leaves the browser, and there is no server fetch. Their logic is in `packages/generators` (`robots-file.ts`, `sitemap-file.ts`, `redirects.ts`, `meta-tags.ts`), each tested against the rules that judge what it writes (the robots file against the robots rules, the sitemap against the sitemap reader, the tags against the title, description, sharing and viewport rules).
- **Sitemap entries are now facts.** `collectSitemap` of a `urlset` also gives `urls` (`readSitemapUrls`): each `url`'s `loc`, `lastmod` and `xhtml:link` alternates, the first 5,000 entries and at most 200 alternates each, with how many there were. It walks the `<url>` blocks the way `readSitemapLocs` walks `<loc>`: one scan, linear in the body, never throws. The sax reader that validates the file is untouched.
- **`sitemap-lastmod-invalid`**: a `lastmod` that is not a W3C datetime on a real calendar day (`lib/w3c-date.ts`, shared with the sitemap generator), and ten entries or more all dated the same (our threshold, said in the copy). It does not say a date is false, and it does not compare with today's date: a rule must give the same verdict for the same page.
- **`hreflang-sitemap-invalid`**: an entry that leaves out itself, an alternate that is an entry of the same file and does not list the entry back, a code Google does not accept (the same `checkHreflang` as the page rules), an alternate that is not a full address. An alternate that is not an entry of the file is left alone: it may be in another sitemap.
- **`outbound-links-found` is information.** It lists the sites a page links to, with how many links and how they are marked (`nofollow`, `sponsored`, `ugc`); nothing is deducted. Because an information rule reports on any page with an external link, 23 existing fixtures gained an `expect.json` naming it (the mechanism M10.1 added for right fixtures).
- **The redirect tools refuse what could break a config**: a space, a quote, a bracket, a semicolon, `$`, `%`, a query or a star in an old path. Arabic paths are written decoded for Apache and nginx (which match the decoded path) and encoded for `_redirects` and `vercel.json`. We could not run the four servers; the copy says to test an old address after deploying.
- **`example-check` reads sitemap examples**: an `xml` example that is a `urlset` or a `sitemapindex` is judged as a sitemap named in robots.txt, the way the scan fetches one.
- **The serp preview's limits are conventions.** 600 pixels for a title (measured in the browser's canvas at 20 px sans-serif) and 160 characters for a description are what search tools use; Google publishes neither, and the page says so.

## 3. Left out of this batch, and why

- `llms-txt-check`: a neutral file check the plan itself says to keep out of the score, and it needs a new fetch collector across engine, API and the three scan UIs. Not worth that for information with no known effect.
- `cookie-consent-check`, `answer-readiness`, `content-quality`, `entity-consistency`, `schema-coverage`, `rich-results-check`: heuristics we could not give an honest wrong and right example for, or that repeat a rule that exists (`brand-name-consistency`, `structured-data-check`). Decided one by one in batch 4.

## 4. Tests

Generators: 40 new cases (robots, sitemap, diff, redirects, meta tags, serp). Rules: two sitemap rules (fixture sites with a robots.txt and a sitemap, the same way `sitemap-invalid` has them) and the information rule. Collector: `readSitemapUrls` and the `urls` of a check. Browser: robots, sitemap and redirect generators in the three engines. Golden pages 43 (wrong) and 44 (right) for the two sitemap rules. The reports come from CI's `golden-actual`.
