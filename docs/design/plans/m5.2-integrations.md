> **ملخص للمالك:** النصف الثاني من المرحلة 5 (مساعد الإصلاح مؤجَّل لغياب مفتاح Claude). **إجراء GitHub** (`integrations/github-action`): تضعه في أي workflow فيفحص صفحة أو عدة صفحات عبر الـ API العام بمفتاحك، وينتظر الفحص بأدب (كل 3 إلى 10 ثوانٍ)، ويكتب ملخص المهمة (الدرجة وأسوأ المشكلات وروابط القواعد) بالعربية أو الإنجليزية، ويفشل الخطوة عند `fail_on` (حرجة أو خطيرة)، ويكتب ملف **SARIF** لتظهر المشكلات في «Code scanning» على GitHub. **إضافة Chrome** (`integrations/chrome-extension`، Manifest V3): تضغط «افحص هذه الصفحة» فترى الدرجة وأسوأ المشكلات وتظهر الدرجة على أيقونة الإضافة؛ المفتاح من صفحة الإعدادات، وبدونه تفتح صفحة الفحص في الموقع. بلا تحليلات ولا شيفرة من الخارج وبأقل الأذونات. كلاهما قسم في `/developers`. **المطلوب منك:** نصوص الواجهة العربية (`reviewed: false`) والنطاق الافتراضي `arablyzer.com`؛ ولنشر الإضافة حساب مطوّر في Chrome Web Store (5 دولارات مرة واحدة)، ولإدراج الإجراء في GitHub Marketplace مستودع عام مستقل (انظر القسم 4).

**Goal:** A workflow scans pages and sends the findings to code scanning; a person scans the open page from Chrome. Both only ever call the public API (v1) with the person's own key, so every quota, limit and egress rule of the API applies.

Design source: `m5.1-public-api.md` (the v1 contract: envelope, error codes, `Retry-After`, ten-minute reuse), `packages/api-contract`.

## 0. Measured before planning (2026-10-11)

| Question | Result |
|---|---|

An extension page cannot read its answers without a host permission, so the manifest asks for `https://arablyzer.com/*` and nothing broader at install; another address (a self-hosted service) goes in `optional_host_permissions` and is requested at runtime, one origin at a time. |

## Global Constraints

- **Only the public API.** Both use `POST /api/v1/scans`, `GET /api/v1/scans/{id}`, `GET /api/v1/scans/{id}/report` (and `GET /scans?limit=1` to test a key). Reuse within ten minutes is the API's: a repeat scan is free.
- **Polite polling**: 3, 3, 4, 5, 6, 8, then 10 seconds; `Retry-After` obeyed on 429; four transient failures in a row end the wait; a deadline (`timeout_seconds`, 300 by default; 3 minutes in the popup).
- **The key is never printed**: the Action masks it (`::add-mask::`), error text is the Action's own strings (never the API's message), `User-Agent` is `arablyzer-action/<version>`. The extension keeps it in `chrome.storage.sync` as asked (it follows the person's Chrome account; the options page says so).
- **Nothing from a scanned page becomes markup or a command.** The job summary escapes every message, selector and address (code spans for the last two); log lines are one line and never start `::`; outputs use a random heredoc delimiter; the popup builds elements with `textContent` only (no `innerHTML`).
- **Extension: minimum permissions.** `activeTab`, `storage`, host `https://arablyzer.com/*`; no background worker, content script, `tabs`, `cookies`, `history`, `webRequest`; CSP `script-src 'self'`, `style-src 'self'`, `object-src 'none'`; no inline script or style; no analytics; no remote code.
- **No new runtime dependency.** `integrations/core` imports only types from the contract and the report schema; both bundles carry no Zod. Lint: `fetch` is handed over in three entry files and taken as an argument everywhere else.
- UI on the R7 scale (the sections of `/developers`), no `style=` (CSP); popup colours are the site's tokens, light and dark; every new Arabic string `reviewed: false` (`packages/i18n/src/integrations.ts`). Commits end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

## Review Focus

1. **SARIF is valid and useful**: validated against the OASIS schema on every golden report in both languages; `ruleIndex` matches, each rule once, `helpUri` equals `/rules/<id>` of the language chosen; one run (and category) per page. Task 2.
2. **The Action is safe in a log and a summary**: hostile page text (markdown, HTML, `::`) cannot reach either; the key does not. Tasks 2, 3.
3. **The committed bundle is the source's**: a test runs `dist/index.mjs` as GitHub does (stand-in API preloaded) and CI diffs a rebuild. Task 3.
4. **The extension asks for little and runs nothing remote**: `build.test.ts` checks the permissions, the CSP, the pages and the code of the built output. Task 5.

## 2. Contracts

**Action inputs** `url`, `urls`, `api_key`\*, `api_url`, `fail_on` (critical, serious, none), `wait`, `lang` (ar, en), `sarif_dir`, `timeout_seconds`, `max_issues`. **Outputs** `score` (lowest), `scores`, `findings`, `report_urls`, `sarif_dir`, `result` (pass, fail, error, started). Exit 1 when a page could not be scanned or `fail_on` is reached; every page is still tried.

**SARIF 2.1.0** (one file per page in `sarif_dir`): `tool.driver` = Arablyzer (`semanticVersion` of the rule engine, `informationUri`), `rules` only those that found something (`shortDescription`, `helpUri`, `help`, `defaultConfiguration.level`, tags: category and `wcag-x.y.z`); `results` with `ruleIndex`, `level` (critical, serious → error; moderate → warning; minor, info → note), `message` in `lang`, `locations[0]` = the finding's page address (+ `region` when the finding has a line) and the selector as a `logicalLocation`, `partialFingerprints['arablyzer/v1']`; `automationDetails.id` = `arablyzer/<host><path>/`; `properties.score`.

**Extension** manifest v3 as in the constraints; the popup states: loading, unsupported tab, no key (open the site's scan form with the address filled in, or add a key), ready, scanning (queued, running), done (score and band, counts, five worst rules with links, full report), error (a message per API code, with `Retry-After`); the badge is the score, coloured by the report page's bands (90, 50). A scan the popup started is picked up again if it is reopened on the same page within ten minutes.
