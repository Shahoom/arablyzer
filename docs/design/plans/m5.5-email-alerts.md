# M5.5 Email alerts (Resend) — Implementation Plan

> **ملخص للمالك:** تنبيهات البريد جاهزة ومطفأة: لا تعمل حتى تضبط `ARABLYZER_MAIL_PROVIDER=resend` مع `RESEND_API_KEY` و`ARABLYZER_MAIL_FROM` و`ARABLYZER_MAIL_SECRET`. يخرج البريد من نطاق فرعي مخصّص للرسائل الآلية (مثل `send.arablyzer.com`) عبر Resend فقط، وترفض الواجهة البدء إن كان المرسِل على النطاق الرئيسي أو على بريد شخصي، فلا يمرّ أي بريد آلي عبر حساب Google Workspace الخاص بك. كل رسالة فيها رابط لإيقافها وترويستا `List-Unsubscribe` (نقرة واحدة)؛ وإيقاف التنبيهات من الرابط يطفئ البريد وحده ويبقي الباقي. صار لكل تشغيل سجلّ للقنوات التي وصلتها، فلا يتكرر الإرسال إلى قناة وصلتها حتى لو فشلت قناة أخرى. **ينتظرك:** حساب Resend، ونطاق فرعي مع سجلات DNS (SPF وDKIM وDMARC)، ومفتاح API، وسرّ عشوائي؛ وقراءة النص العربي الجديد (`reviewed: false`).

**Goal:** A person who turns on "email" in their alerts gets the monitor's alerts (a score drop, a new critical finding, a site that cannot be scanned, the optional weekly summary) at the address they signed in with, from a sender that is not the owner's Google Workspace, with a working way to stop them. Off until the owner sets the provider.

Built on `m4.3-monitoring.md` (the `Mailer` interface and the scheduler's `deliver`, which M4.3 left off).

## Design

| Question | Decision |
|---|---|
| Provider | Resend over its HTTP API, through `safeFetch` and the egress proxy (the API reaches nothing else directly). No SDK: one POST. Switch: `ARABLYZER_MAIL_PROVIDER=resend`; unset or `off` is off and nothing else is read |
| Sender | `ARABLYZER_MAIL_FROM` must be on a **subdomain of the site's domain** (`send.arablyzer.com` for `arablyzer.com`); the apex, a look-alike suffix and personal domains (gmail, outlook, …) stop the start. Replies are not read (no `Reply-To`; the footer says so). A spam complaint then lands on the sending subdomain's reputation, never on the domain people's mailboxes use |
| Half-set provider | `RESEND_API_KEY`, `ARABLYZER_MAIL_FROM` and `ARABLYZER_MAIL_SECRET` (≥ 32 characters) are all required once the provider is named, in the API and in the monitor: it refuses to start rather than let the owner believe alerts are mailed |
| Consent | Opt-in, per account: the existing «البريد الإلكتروني» switch on `/account` (default off, shown only when a provider is on), to the Google-verified address of the account. A test button sends one message to that address (3 per 10 minutes) |
| Unsubscribe | Every mail carries a link and `List-Unsubscribe` + `List-Unsubscribe-Post: List-Unsubscribe=One-Click` (RFC 2369, 8058). The token is the account id and an HMAC of it under a key derived from `ARABLYZER_MAIL_SECRET` and one purpose string; it has no table and no expiry (an old mail must still stop the mail), checked in canonical form, and can do one thing: set that person's `email` alert off. `GET /api/mail/unsubscribe?t=` shows a page (Arabic and English together, no script, no style, own CSP) and changes nothing, because link checkers open every link; its button, or a mail client's one-click `POST` (no cookie, no Origin), does it |
| No double send | `monitor_runs.delivered text[]` (migration `0011_alert_delivery`): each channel an alert has reached is recorded, and the retry of a run (backoff 1 min … 6 h) sends only to the others. Before this, a webhook that had delivered would have been sent again whenever the other channel failed. Resend also gets an `Idempotency-Key` (`alert-<scan>-email`), so a lost answer cannot mail twice. The weekly summary is sent once to each channel with no retry (summarised when at least one took it) |
| A failing provider | `send` never throws; 2xx is sent, 400/422 is refused for good (counted as handled, not retried), everything else (429, 5xx, 401/403 for a key or domain not set up, no answer) is retried with the same backoff, then given up. The webhook and the monitor's runs are untouched either way; the log gets a status code, never a key, an address or a body |
| Bounces and complaints | Resend suppresses addresses that bounced or complained on its side. Nothing of our own is built for them |
| Content | Text and a small HTML part, in the account's language (right to left for Arabic); the same sentences as the webhook, then why the person gets it, "replies are not read" and the unsubscribe link. Every value is escaped; the subject cannot hold a line break |

## Tests

Sender rules (apex, look-alike, personal domains, line breaks); config (off by default; complete; each missing variable stops the start; the links outlive a provider that is switched off); Resend (payload, key only in a header, idempotency key, every status → outcome, a throwing or silent provider, the log never holds the key or the address); tokens (round trip, wrong secret, tampered, non-canonical, truncated, another person's); the mail (Arabic is RTL, HTML is escaped, subject on one line, headers); routes (test mail, its limit, 404 without a provider, 401 signed out, 400 from another origin; GET asks and changes nothing, POST turns email off with no cookie, bad tokens 400, no style attribute or script on the page); scheduler (mail goes out only when asked and in the account's language; a channel that has the alert is never sent it again, in either direction; a provider that throws neither blocks the webhook nor the run and is given up after the attempts; a refused address is not retried; the summary goes once); the PostgreSQL contract (run here against a local PostgreSQL 16).

## Not in M5.5

WhatsApp (M5.6). A second provider. Own handling of bounces and complaints (Resend's suppression list does it). Marketing mail, digests other than the existing weekly summary, a "manage" page beyond the account page's switch. Verifying the address beyond what Google already verified.

## For the owner

1. A Resend account (resend.com); the free plan is enough to start.
2. Add the sending domain in Resend's dashboard as a **subdomain**, e.g. `send.arablyzer.com`, and add the DNS records it shows (SPF, DKIM) at the DNS provider, plus a DMARC record. Nothing is changed on the main domain's mail or on Google Workspace.
3. Create a Resend API key (sending access) and set, in the deployment: `ARABLYZER_MAIL_PROVIDER=resend`, `RESEND_API_KEY`, `ARABLYZER_MAIL_FROM="Arablyzer <alerts@send.arablyzer.com>"`, `ARABLYZER_MAIL_SECRET` (`openssl rand -base64 32`; do not change it later, or old unsubscribe links stop working).
4. Read the Arabic of the mail and the unsubscribe page (`reviewed: false`).

Not tested against Resend itself (no account): the real request is checked against its documented shape and status codes with a stand-in.
