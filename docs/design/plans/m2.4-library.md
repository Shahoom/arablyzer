## 1. The rule library (M2.4a)

**A page per rule, in both languages**, in the approved Rule board: the heading; chips with the rule's id, severity,
category, version and what it reads (the HTML, robots.txt, browsers, Chrome's data); why it matters; the live example;
how to fix; how we detect, as numbered steps; the references. Beside it: its weight in the score (from
`packages/scoring`, so the page cannot drift from the score), the tools that run it and the full scan, and rules of its
category. JSON-LD: a `TechArticle` with the rule's version, and the breadcrumb.

**The live example** (§6.2 «مثال حي») is an excerpt of the rule's own fixtures, `rules/<id>/example.md`: two code
blocks, the wrong and the right. A test holds each to the truth: the wrong one is in a `wrong*` fixture and in no
`right*` one, the right one the other way round, whitespace aside. The fixtures are what the rule's tests run (and, for
the rules that render, what the engine's browser suite renders in three engines), so the page shows exactly what the
rule judges. The same excerpt serves both languages, as the fixtures do. Seven rules show none, since what they judge is
not in the page's files: the three Core Web Vitals (Chrome's visitor data), the certificate, HTTPS, the HSTS header and
compression; their fix sections show the code to write.

**The library's index** lists the rules by category, the Arabic layer first, with the same search as the tools'
directory. "Rule library" joins the header.

**Links in.** Every rule a tool page runs links to its page, and so does every finding in a report and a tool's result
(BUILD-PLAN §6.2: «كل مخالفة في أي تقرير تربط هنا»).

**The self-audit** holds every rule page to the template: the sections in order (the example when there is one), text
in each, a link to a source in the references, the `TechArticle` and the breadcrumb, and everything every page needs.
Lighthouse and the three-engine self-scan take the first rule page in each language, as for the tool pages.

**A page about a problem shows the problem.** The tatweel rule's page quotes a stretched word, the digits rule's page
Eastern and Persian digits, the prices rule's page a price with two decimals, and the site's own rules failed those
pages. The rules already leave text in code alone (`code`, `pre`, `kbd`, `samp`), which is where a quoted sample
belongs: the copy writes them in backticks, as the tools' copy does. Nothing is exempted.

## 2. The bot (M2.4b)

**What the plan asks** (§13): a scan a person asks for is a browser's visit with a named user agent; the deep crawl and
the yearly crawl respect robots.txt; `/bot` explains the bot and lets a site opt out.

**The opt-out.** A site that names ArablyzerBot in its robots.txt and disallows a page is not scanned there: the scan
reads robots.txt before the page, and before following each redirect to a page, stops before asking for a page the
site disallows, and the report says the site asked not to be checked, with its rule. Only a group that names the bot
counts: `User-agent: *` addresses crawlers, and a scan someone asks for is not a crawl. A robots.txt that cannot be read
lets the scan go on. Every scan reads robots.txt afresh, so the opt-out holds from the next scan. A list of sites
excluded on request needs a contact address, which is the owner's (§20).

**`/bot`** says who the bot is and what it does, from the code: its user agent, when it visits (only when someone asks
for a check of that page), what it fetches, what it never does (submit a form, type into a field, log in, get past a
challenge), its limits, and how to opt out.

**`/methodology`** renders `docs/methodology.md`, the Arabic at `/methodology` and the English part at
`/en/methodology`: the page the tool pages and the reports link to, on the site instead of GitHub.

**404 pages** in both languages, the English one for paths under `/en/`, served by Caddy with the 404 status.

## 3. Being found (M2.4c)

- **robots.txt** allows everything but `/api/`, and names the sitemap. Reports stay crawlable, so search engines can
  read their `noindex`.
- **Sitemaps**: an index at `/sitemap.xml` and one sitemap per section (`pages`, `tools`, `rules`; `fix` and `glossary`
  when they come), each URL with its hreflang alternates, and `lastmod` where a page has a date (the tools' `updated`).
  Written at build for the site's origin.
- **IndexNow**: the key is the deployment's (`ARABLYZER_INDEXNOW_KEY`); the build writes its key file, and
  `pnpm indexnow` sends the changed URLs after a deploy. Deploying is the owner's decision, so nothing is sent before.
- **Open Graph images**: one 1200×630 image per page, drawn by Chromium at build from a template in the Lab design, so
  Arabic joins as it does on the page. The `og:image` gap the audit has carried since M2.1 closes.

## 4. `/fix` and the glossary (M2.4d)

- **`/fix`**: a guide per Search Console or Merchant Center message, titled with the message as Search Console shows it,
  in Arabic and in English (people paste the message into a search), then what it means, why it happens, how to fix it,
  and the Arablyzer tool or rule that checks it. The first fifteen are the Page indexing report's reasons, taken from
  Google's documentation, not from memory.
- **`/glossary`**: a page per term, with the English term, a short definition, an example and links to the tools and
  rules that use it. No page without enough to say: a thin page is worse than none (§6.5, doorway pages).

## 5. Record (M2.4a)

**Built:** `/rules` and a page for each of the 47 rules, in both languages; each rule's example (40 of them) from its
fixtures, tested; the rule page template in the self-audit; links to the rules from tool pages, from a tool's result and
from every finding in a report; "Rule library" in the header. CSS and JSON examples are highlighted as HTML ones are,
and the examples wrap rather than scroll: they are short, and often a sentence long.

**What checking found:**

- **The rules' pages quoted what the rules flag** (a stretched word, Eastern and Persian digits, a price with two
  decimals), in prose, and the site's own rules failed them. The samples are in code now, as in the tools' copy.
- **An ISO date in Arabic text is drawn reversed.** The products rule's page said the ISO 4217 list was published on
  «2026-09-17», which Chromium draws as 17-09-2026 in Arabic text; the bidi isolation rule flagged it when the site
  scanned itself. The Arabic says the date in words.
- **One rule's fixtures could not show a difference in text**: the canonical rule's right page is the same file as a
  wrong one whose fault is in its headers. The example test leaves out a fixture that differs from one of the other kind
  only where no excerpt reaches.
- **The mojibake rule's right page was about something else** (French words in Arabic text), so its example could not
  show the fix. It has a right fixture with the same reviews read as UTF-8 now.

**Checked (2026-09-29, the owner's Mac), with M2.2b merged in:** the site's self-audit (162 pages), the site scanning
itself in Chromium and Firefox (every page, every rule), the rules' tests (every example against its fixtures), unit
tests, lint, types and formatting.

## 6. Record (M2.4b)

**Built:** the opt-out in the engine, the CLI and the site; `/bot` in both languages, each number on it the code's own
(bot.json); `/methodology` from `docs/methodology.md`, which the tools, the rules, the reports and the home page link
to instead of GitHub; the 404 pages, which Caddy serves with the 404 status under each language; the methodology and
the bot in the footer.

**How the opt-out works** (the engine's `scan`): robots.txt of the page's site first, through the same policy as every
request; before each redirect is followed, robots.txt of the site it leads to (at most ten more); a group naming the
bot that disallows the page stops the scan before the page is asked for: the scan is `failed`, every rule `error`
`opted-out`, the page and its facts left out, and the notice gives the rule, its line and robots.txt's address. The
robots rules reuse the final site's robots.txt, and `facts.robots` appears only when they run, so reports of other
scans have not changed. A scan asks for one more file than before, robots.txt, with the usual timeout.

**What checking found:**

- **The first design fetched a redirect target's page before reading its site's robots.txt**, and discarded it: the
  bot's page says the check stops before fetching a page it is asked not to. The egress fetch gained a hook before each
  redirect, and the scan reads robots.txt there.
- **Formulas in Arabic text read right to left.** The methodology's worked examples (`100 × (1 − 10 ÷ 25) = 60`) are in
  code now, so they read as written, on the site and on GitHub.

**Checked (2026-09-29, the owner's Mac):** the site's self-audit (168 pages), the site scanning itself in Chromium and
Firefox (184 browser tests: every page, the tool page's states, the opted-out card), unit and SSRF tests, the CLI's
end-to-end tests with a site that opts out, lint, types, formatting and the report schema; the 404 pages in a
throwaway `caddy:2.11` container.

## 7. Record (M2.4c)

**Built:** `/robots.txt` (every page open to crawlers but `/api/`, reports included so their `noindex` is read, and the
sitemap named); `/sitemap.xml`, an index of three sitemaps (`pages`, `tools`, `rules`), each page in Arabic and in
English with the hreflang of both and x-default, the tools with their `lastmod`; an Open Graph image for every page
shared as a link (164 pages and the report template), 1200 × 630, with `og:image`, its size and alt, and a large Twitter
card; the IndexNow key file when the deployment has a key (`ARABLYZER_INDEXNOW_KEY`), and `pnpm --filter @arablyzer/web
indexnow` to send the sitemaps' addresses after a deploy, which nothing runs before the owner deploys.

**The images** are drawn by Chromium after Astro builds the site (`scripts/og-images.ts`): a card in the Lab design with
the page's heading, its description, and what it is (a tool's category, a rule's id, the section), from HTML with inline
fonts and every request refused. The card reads its colours from `global.css`'s tokens, so a redesign redraws them. The
build needs Chromium now: CI builds the site in the job that has it (with its self-audit and Lighthouse), and the
Docker image builds it in the browsers' stage, whose fonts and versions are fixed; drawing the cards takes about six
seconds.

**The self-audit** checks both ways that the sitemaps list every page to index and nothing else, and that every page
shared as a link names an Open Graph image the build drew. The `og:image` gap the audit carried since M2.1 is closed:
the list of known gaps is empty.

**Checked (2026-09-29, the owner's Mac):** the self-audit (168 pages, the sitemaps and 166 images), the site scanning
itself in Chromium and Firefox (184 browser tests), unit tests, lint, types and formatting; the web image built with
Docker, drawing the 166 images in the browsers' stage.

**Found on the way:** the form rules' pattern check gives each pattern 50 ms, and a machine busy enough (a Docker build
beside the tests) made one test's pattern take longer, so the rule did not fire: a result that depends on the machine's
load. It passes alone; making the check count work rather than time is left for a change of its own.


## 8. Record (M2.4d)

**Built:** `packages/guides`, the `/fix` guides and the glossary as Markdown in both languages, read by one strict
parser (each kind's sections, in order, and the guides' FAQ), with registries that give each guide's message verbatim
from Google's Page indexing help in English and in Arabic, and the tools, rules, guides and terms around each piece.
Fifteen guides: every reason the report gives for a page not being indexed, except "Blocked by page removal tool". And
thirty-eight terms, the words the tools and rules use. On the site: `/fix` and `/glossary`, with their indexes (the
guides grouped as the report groups them, the terms in the order of their names), each page with its sections, the
message in the other language, and what is around it. Each has TechArticle or DefinedTerm JSON-LD, a breadcrumb from
the home page, a sitemap of its own and share images.

**Written from the documentation:** five writers checked each fact against Google's, the W3C's and MDN's pages, and
left out what those pages do not say: a maximum URL length, whether Google honours `Retry-After`, HTTPS as a ranking
signal. Google's pages disagree on whether the URL Inspection live test follows redirects; the guides use the Search
Console Help's wording.

**Links in Arabic copy** follow the convention of the owner's reviewed rules: Google's Arabic page where Google
publishes one that says what the text cites, otherwise the English page marked «(بالإنجليزية)». All 46 marked links
to Google's documentation, 23 pages, had such an Arabic page, checked with its anchors, and now link it. Google marks
these pages as machine translations; the reviewed rules link the same kind. Other sites' Arabic machine translations
(web.dev, Chrome's documentation) stay in English.

**Fixed on the way:**
- Three references of the rules' copy that no longer led where they said: ar-tatweel's Unicode FAQ page, which moved
  and never named tatweel (the Arabic code chart does), and two anchors of the W3C's Arabic layout requirements.
- robots-blocks-googlebot credited Google's documentation with the typo tolerance of Google's open-source parser. It
  now cites the parser, and waits for the owner's review again, since its Arabic changed after the review.
- CrUX had two Arabic names; it has the rules' one.
- The `/fix` index said there was a guide for every message; it now describes the guides it has.
- The two indexes were in no sitemap; the audit found it.

**For the owner:** the Arabic of every guide and term (`reviewed: false`), and a few words:
- «الفهرسة أو الأرشفة (indexing)», a title that carries both searched words.
- «علامة noindex» (Search Console's word) beside «وسم» for other tags.
- CLS's name in Google's Arabic, «متغيّرات التصميم التراكمية».
- WCAG, which the W3C's authorised Arabic translation calls «مبادئ النفاذ إلى محتوى الويب».

- The site scanning each of its pages with its own rules: the pages that stand for the rest in every engine here,
