# M4.9: the signed-in dashboard («لوحة المستخدم»)

The owner sent a purchased template (Jampack, a Next.js and Bootstrap SaaS dashboard) and asked, once
a person signs in, where its panel is. Until now a signed-in person got one long `/account` page
(M4.1 to M5.1: sites, history, monitoring, alerts, crawls, PDFs, brand, keys, erasure). The approved
v2 artboards `docs/design/v2/DashHome.dc.html` and `DashSite.dc.html` are the redesign this builds:
a Cloudflare-like app, the sidebar on the right in Arabic, a top bar with search, a sites table with
sparklines, a site page with a chart that answers the pointer, a donut, and a dark theme.

## 1. What we took from Jampack, and what is ours

Jampack is a reference for the shape of an app, nothing else. Its licence (ThemeForest Regular) does not
cover a public repository behind a product with paid plans, so none of its code, CSS, SCSS, images,
icons or fonts is in this repository.

| Taken as an idea | Ours |
| --- | --- |
| A vertical menu in labelled groups, an icon and a count beside each entry | The groups, icons (lucide, already a dependency), words and counts are Arablyzer's; the menu is plain links, not a Bootstrap collapse |
| A top bar with search, a theme switch and a user menu | A site switcher, a search over the person's own sites, scans and pages (`Ctrl+K`), and a menu with language and sign-out |
| A dashboard as a row of figures, a chart and a table | Figures that are the plan's real limits and the person's real scores, one chart (M4.6's, now with a pointer), one table; no template widgets |
| Light and dark | Our tokens redeclared (section 4), not a stylesheet swap |

Everything is written for this stack: Astro 7 pages, Preact islands, Tailwind v4 on the R7/R8 tokens.

## 2. Routes

Arabic at `/app`, English at `/en/app`. Static pages, never indexed (`noindex` in the head, and the
server's `X-Robots-Tag`), not in the sitemap, and **not built at all without accounts**: the build
emits them only when `PUBLIC_AUTH_GOOGLE_CLIENT_ID` is set, so a site without accounts answers 404
(the same switch that hides the header's account link). With the build on and the API's
`ARABLYZER_ACCOUNTS` off, the island says accounts are off, as `/account` did.

| Path | Page | Data |
| --- | --- | --- |
| `/app` | Overview | sites, scans, PDF allowance, keys, histories of monitored sites |
| `/app/sites` | Sites | sites, scans |
| `/app/site?id=` | Site detail | history, last report, crawl |
| `/app/scans` | Scans | scans |
| `/app/monitoring` | Monitoring and alerts | sites, alert settings, histories |
| `/app/crawls` | Deep crawl | sites, the crawl report |
| `/app/pdfs` | PDF reports | the M4.7 list |
| `/app/keys` | API keys | the M5.1 list |
| `/app/brand` | Brand (white-label) | the M4.7 settings |
| `/app/account` | Account and plan | account, limits, erasure |

A site's id is in the query, not the path: the site is static, and one page serves every site (the
comparison page does the same). `/account` and `/en/account` stay: signed out they still show the
sign-in; signed in they go on to `/app`. `/login` ends at `/app`. `/account/compare` is unchanged.

## 3. Structure

- `AppLayout.astro` (no site header or footer), `components/app/AppPage.astro`, and one rest route
  `pages/app/[...page].astro` (and `en/`), which is where the build decides whether the pages exist.
- One island per page, `islands/app/AppFrame.tsx`, which is the gate (who is signed in; if nobody, to
  `/login`), the shell, and the page's view, loaded as its own chunk (`import()` by page).
- The shell: a sidebar that is 264 px from lg, an icon rail from md to lg, and below md a bottom bar
  (overview, sites, scans, more) whose «more» opens the whole menu in a bottom sheet (a `<dialog>`).
  The top bar: breadcrumb, site switcher, search, theme, user menu. The palette is a `<dialog>`.
- The shell reads sites and scans once and shares them (context), so the switcher, the search, the
  badges and the pages never ask twice. Every page's own data is its own request.
- `islands/app/app-model.ts` is pure and tested: paths, search, deltas, sparkline geometry, meters,
  alerts from histories, donut arcs, the scans filter and pages.
- Existing panels (alerts, PDFs, brand, keys, the crawl report, the PDF button, the score chart) are
  reused where the page is the panel; the sites and the history, which were one card, are new.

## 4. Dark theme

`html[data-theme='dark']` redeclares the colour tokens (`app.css`, loaded by the app layout only; the
public pages stay light). A hashed inline script in the app's head sets the attribute before the first
paint from `localStorage` (`arablyzer-theme`: `light` or `dark`) or, with none, `prefers-color-scheme`,
so nothing flashes; its hash is added to the page's policy. The toggle writes the choice. Components
that paint a literal white (`btn-white`, `chip`, `search-field`) are overridden for dark in the same
file. `test/tokens.test.ts` checks the dark text pairs at 4.5:1 as it does the light ones.

## 5. Data and what is not there

Only existing routes. Meters are the limits the API already gives: saved sites, monitored sites
(`GET /api/sites`), PDFs of the month (`GET /api/pdf`), API keys (`GET /api/account/keys`), and the
days scans are kept (`GET /api/account/scans`). A site's sparkline is the scores of its scans in the
history. Alerts are the markers the monitor already computes in a site's history (a drop, a new
critical, a site down), for the most recent monitored sites. The donut is the failed rules of the
site's last report by severity.

Not there, and said on the pages: a plan's name and billing (the paid plans are «قريباً»; nothing
exposes a plan name), a team, and a notification feed that is not the monitor's.

## 6. Quality

Charts are inline SVG with a title, a summary and a table; the pointer, and the arrow keys on the
focused chart, move a cursor and a readout; reduced motion stops the line's draw. No style attribute
in markup the server renders (CSP); a width set from data is set on the client. Right to left is the
design's direction: the sidebar is at the start edge, arrows and icons that point mirror, time in a
chart starts at the start edge, addresses are `dir="ltr"`. Phone: 390 px, no horizontal scroll, 44 px
targets, the bottom bar clear of content.

Screenshots (phone 390 and desktop 1440, light and dark) are in the session scratchpad
(`dash-shots/`); they are not in the repository.
