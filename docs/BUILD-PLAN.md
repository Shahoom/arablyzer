# Arablyzer — خطة البناء الكاملة (LAB-001)

> **محلّل المواقع العربية** — أول مشروع في مختبر كلاود توبيا.
> الكود مفتوح المصدر · الموقع المستضاف مجاني أساساً مع اشتراك للاستخدام الكثيف · تاريخ الخطة: 2026-09-24
>
> تحلّ هذه الوثيقة محل خطة «Cloudster» السابقة. المصطلحات التقنية وأسماء الملفات والمسارات بالإنجليزية
> عمداً حتى تُنسخ كما هي.

## 0. الملخّص

**ما هو Arablyzer؟** صندوق أدوات لفحص المواقع (على طريقة [Shipwork](https://shipwork.io/): أكثر من
100 فحص، كل فحص صفحة مستقلة مجانية)، يرى موقعك كما يراه **Google** و**ChatGPT** و**الزبون العربي على
جواله**. يغطي كل ما تغطيه أدوات الـ SEO العالمية (الزحف، الأرشفة، السرعة، البيانات المنظّمة، الروابط،
الأمان، زواحف الذكاء الاصطناعي)، ويضيف فوقها طبقات لا يقدّمها أحد: **العرض العربي عبر المتصفحات**،
**الخطوط العربية**، **RTL**، **نماذج الإدخال بالعربية**، **SEO عربي يفهم صرف الكلمة**، **متاجر الخليج
(سلة وزد)**، **واتساب**، **أعراف التوطين الخليجي**.

**النموذج:** open-core
- الكود كاملاً على GitHub (ترخيص **AGPL-3.0** — القسم 3).
- الموقع المستضاف **مجاني أساساً**: كل الأدوات تعمل بلا تسجيل.
- **اشتراك Pro/Agency** لمن يحتاج استخداماً أعلى: مراقبة يومية لمواقع كثيرة، زحف آلاف الصفحات،
  تكامل Search Console، تنبيهات واتساب، تقارير PDF بعلامة الوكالة، حصص API أكبر.
- الاستضافة الذاتية مجانية للأبد بكل الميزات.

**الـ SEO هو المنتج نفسه:** كل أداة صفحة تستهدف بحثاً حقيقياً بالعربية والإنجليزية؛ مكتبة القواعد،
أدلة «تعلّم» و«صلّح الخطأ»، مفكك رسائل أخطاء Search Console بالعربي، مسرد مصطلحات، وتقرير سنوي
«حالة الويب العربي» مع بيانات مفتوحة = آلة روابط وزيارات. التفاصيل في القسم 6.

**المحرّك برمجي 100%.** الفحص والزحف وكل أدوات الـ audit كود حتمي: جلب HTTP، قراءة robots.txt
وsitemap، تحليل HTML، عرض الصفحة في متصفح بلا واجهة (Playwright)، قياس الأنماط والخطوط والاتجاه في
الـ DOM، axe-core وLighthouse، فحوص DNS وTLS مباشرة، زحف الروابط الداخلية بحدود. نفس الموقع يعطي نفس
النتيجة كل مرة. **الذكاء الاصطناعي اختياري** (شرح إصلاح مخصّص عند الطلب، إشارات لغوية، تصنيف التقرير
السنوي) ولا يدخل أبداً في المخالفات أو الدرجة — ويمكن الإطلاق وهو مُطفأ بالكامل.

**التقنيات باختصار:** TypeScript/Node للمحرّك والعمّال (Playwright بثلاثة محرّكات + axe-core +
Lighthouse)، **Astro** للموقع (صفحات ثابتة سريعة جداً = SEO)، **Hono** للـ API، **PostgreSQL**،
**BullMQ/Valkey**، **Parquet + DuckDB**، **Cloudflare** (DNS/WAF/Turnstile/R2/Pages)، VPS للعمّال،
**Claude** لمساعد الإصلاح. التفاصيل والأسباب في القسم 8.

**المدة التقديرية** (مطوّر واحد متمرّس مع Claude Code — تقدير لا وعد): إطلاق عام بـ 40 أداة خلال
**10–14 أسبوعاً**؛ المنصة كاملة (~110 أدوات + اشتراكات + تكاملات) خلال **7–9 أشهر**.

## 3. النموذج التجاري (open-core)

**الترخيص: AGPL-3.0** لكامل المستودع (نفس نهج Plausible Analytics).
- يسمح لأي أحد بالاستخدام والتعديل والاستضافة الذاتية مجاناً.
- يُلزم من يشغّل نسخة معدّلة كخدمة للآخرين بنشر تعديلاته → يحمينا من منافس يأخذ الكود ويبيعه مغلقاً.
- بديل: حزم `rules` و`cli` و`collectors` تحت Apache-2.0 لتسهيل تبنّيها داخل أدوات أخرى (قرار — القسم 20).

**الخطط** (الأرقام قرار المالك؛ مرجع السوق: Shipwork يبدأ من 12$/شهر):

| الخطة | لمن | ماذا تتضمن |
|---|---|---|
| **مجاني بلا تسجيل** | الجميع | كل أدوات الصفحة الواحدة، الفحص الفوري، رابط تقرير قابل للمشاركة — مع حدود معدل لمنع الإساءة |
| **مجاني بحساب** | أصحاب المواقع | حفظ المواقع، سجل الفحوص، مراقبة أسبوعية لموقع واحد، زحف حتى ~100 صفحة |
| **Pro** (شهري/سنوي) | المستقلون والشركات | مراقبة يومية لعدة مواقع، زحف آلاف الصفحات، ميزات Search Console، تنبيهات **واتساب**، تقارير PDF عربية، حصة API، حصة مساعد الإصلاح بالذكاء الاصطناعي |
| **Agency** | الوكالات | كل Pro + تقارير بعلامة الوكالة (white-label) بالعربي، مساحات عمل للعملاء، حصص أعلى |
| **استضافة ذاتية** | المطوّرون والجهات | كل الميزات مجاناً على بنيتهم (AGPL) |

**الدفع:** مزوّد «Merchant of Record» (مثل Paddle أو Lemon Squeezy) يتولّى الضرائب والفوترة عالمياً —
**يُتحقق من دعمه لكيان كلاود توبيا (عُمان/تركيا) قبل الاختيار**. وسائل دفع خليجية (مدى، STC Pay) لاحقاً
عبر بوابة إقليمية (مثل Tap أو Moyasar) إن طُلبت.

**مصدر دخل ثانٍ لكلاود توبيا:** كل مخالفة فيها زر «صلّحها لي» → واتساب (نقطة `/api/whatsapp`) + تسجيل
lead في نظام كلاود توبيا، مع ربط المخالفة بالخدمة المناسبة.

> ⚠️ **تعارض يجب حسمه:** صفحة المختبر تقول «لا شيء مما يخرج منه للبيع». مع خطة مدفوعة يجب تعديل النص
> إلى صيغة صادقة مثل: «الكود والبيانات وطريقة القياس مفتوحة ومجانية دائماً؛ بعض الخدمات المستضافة
> تقدّم خطة مدفوعة للاستخدام الكثيف» — أو إدراج Arablyzer في /products أيضاً (القسم 20).

## 4. المبادئ

1. **الكود مفتوح** والمنهجية منشورة؛ البيانات السنوية CC BY 4.0.
2. **كل رقم مع مصدره وطريقة قياسه.** صيغة الدرجة منشورة؛ كل مخالفة معها دليل (المحدِّد، القيم، لقطة).
3. **العربية هي الأصل:** تُكتب النصوص بالعربية أولاً، وتُختبر بالعربية أولاً.
4. **صادقون في الحدود:** لا ندّعي «امتثالاً»؛ نفصل «فشل آلي» عن «يحتاج مراجعة بشرية»؛ ولا نخمّن
   حقولاً لا نراها (نفس مبدأ Shipwork: honest about limits).
5. **Arablyzer يجتاز فحوصه بنفسه** في كل نشر.
6. **المجاني حقيقي:** كل أداة صفحة واحدة تبقى مجانية بلا تسجيل. الاشتراك للحجم، لا لحجب الأساسيات.

### 5.2 الفحص الكامل لصفحة (`/audit`) [MVP]
رابط واحد → كل الفحوص المناسبة معاً → درجة صحة عامة + درجات لكل فئة + مخالفات مرتبة بالخطورة، لكل
منها: ماذا، لماذا يهم إنساناً حقيقياً، كيف تُصلح (مقتطف كود)، الدليل. تقدّم حيّ (SSE). رابط تقرير
قابل للمشاركة، صورة OG تلقائية، طباعة/PDF.

### 5.3 مختبر العرض عبر المحرّكات [MVP]
الصفحة في **Chromium وWebKit وFirefox**: اتصال الحروف، ارتفاع الأسطر، القصّ، الفروقات بصرياً جنباً
إلى جنب. (WebKit في Playwright على Linux ليس Safari حرفياً — يُذكر في المنهجية.)

### 5.4 الزحف العميق (`/deep-crawl`) [v2]
من sitemap والروابط الداخلية، بحدّ حسب الخطة. **تجميع المخالفات حسب القالب**: «هذا الخطأ في 142 صفحة
لأنها من قالب المقال — إصلاح واحد يحل الكل». مقارنة التوأم العربي/الإنجليزي. احترام robots.txt.

### 5.5 المقارنة (`/compare`) [v2]
موقعك مقابل منافس (أو قبل/بعد): فرق الدرجات والمخالفات فئةً بفئة.

### 5.6 الدرجة والتاريخ (`/score`، `/trend`) [v2]
درجة صحة بصيغة منشورة، ومنحنى عبر الزمن، و«ما الذي تغيّر» بين فحصين.

### 5.7 المراقبة والتنبيهات [v2]
إعادة فحص يومية/أسبوعية حسب الخطة؛ تنبيه عند التراجع أو عند تغيّر مهم (robots.txt تغيّر، sitemap
اختفى، شهادة TLS تقترب من الانتهاء، زاحف ذكاء اصطناعي صار محجوباً). القنوات: بريد، **واتساب**
(WhatsApp Business Cloud API)، Slack/Discord/webhook.

### 5.8 تكامل Google Search Console [v2]
ربط OAuth (نطاق `webmasters.readonly`) → الصفحات المعرّضة لخسارة الزيارات، كلمات «على مسافة قريبة»،
فجوات المحتوى، تفكيك تنافس الصفحات (مع التطبيع العربي).
> ⚠️ نطاقات Google الحساسة تتطلب **مراجعة تحقق OAuth من Google** قبل الإطلاق العام — تُبدأ مبكراً.

### 5.9 مساعد الإصلاح بالذكاء الاصطناعي [v2] — القسم 12.

### 5.10 التقارير [MVP → v2]
- رابط عام غير مُدرج لكل تقرير، قابل للحذف، **noindex دائماً** (القسم 6).
- PDF عربي/إنجليزي [v2]؛ **white-label للوكالات** [v2 Agency].

### 5.11 أدوات المطوّرين
- **CLI**: `npx arablyzer <url>` → نص أو `--json` أو `--sarif` [MVP].
- **GitHub Action** + SARIF → المخالفات داخل GitHub Code Scanning، وحدّ أدنى للدرجة يُفشل الـ PR [v2].
- **API** بمفاتيح وحصص، موثّقة بـ OpenAPI [v2].
- **خادم MCP** (`arablyzer.com/mcp`): «افحص هذا الموقع» من داخل Claude وChatGPT وأي عميل MCP — كاشف
  يفعلها، ويجب أن نفعلها [v2].
- **إضافة Chrome** (MV3): تفحص الصفحة المفتوحة محلياً، تعمل على staging وصفحات الدخول [v2].

### 5.12 تطبيقات منصّات المتاجر [v3]
تطبيق «Arablyzer» في متجر تطبيقات **سلة** و**زد**: يفحص متجر التاجر تلقائياً ويراقبه — قناة توزيع
خليجية مباشرة لا يملكها أي منافس.

### 5.13 الشارة [v3]
شارة قابلة للتضمين («Arablyzer: جاهز للعربية») تُمنح فوق حدّ منشور وتُعاد مراجعتها دورياً. الرابط فيها
اسم العلامة فقط، ونسمح بـ `rel="nofollow"` (لا روابط بكلمات مفتاحية — تتجنّب مخالفة إرشادات Google).

### 5.14 «حالة الويب العربي» — التقرير السنوي والبيانات المفتوحة [v3]
إطار عيّنة منشور مسبقاً (22 دولة × قطاعات)، زحف مهذّب، تصنيف عبر Claude Batch API، **Parquet + CSV
بترخيص CC BY 4.0**، موقع تفاعلي مع **مستكشف بيانات داخل المتصفح (DuckDB-WASM)**، و**Dataset schema**
ليظهر في Google Dataset Search. سياسة التسمية (مجمّع/بالأسماء/مشاركة خاصة أولاً) قرار المالك.

## 6. استراتيجية الـ SEO («الأسطورية»)

الـ SEO ليس قسماً في آخر المشروع؛ **هو معمارية الموقع**. خمسة محرّكات نمو، كلها تُبنى من اليوم الأول:

### 6.1 صفحات الأدوات (المحرّك الرئيسي)
- ~110 أداة × لغتين = **~220 صفحة** قابلة للأرشفة، كل واحدة **أداة تعمل فعلاً** (ليست صفحة هبوط رقيقة).
- كل صفحة أداة تستهدف **عنقود بحث** محدداً، مثل (أمثلة، تُتحقق أحجامها ببيانات حقيقية):
  «فحص سرعة الموقع» / «فحص robots.txt» / «مولد رابط واتساب» / «فحص hreflang» / «hreflang checker» /
  «Arabic font checker» / «RTL checker».
- **قالب صفحة الأداة** (ثابت، يُفرض بالكود):
  1. H1 = اسم الأداة بصيغة البحث + سطر وصف.
  2. **الأداة نفسها فوق الطيّة** (حقل + زر).
  3. «ماذا تفحص هذه الأداة» بنقاط.
  4. مثال خطأ/صحيح **حي**.
  5. «كيف تُصلح» مع كود.
  6. أسئلة شائعة (نص حقيقي في HTML — يخدم إجابات الذكاء الاصطناعي).
  7. روابط داخلية: القواعد المرتبطة، الأدلة، أدوات مجاورة.
  8. تاريخ آخر تحديث + منهجية.
- Schema لكل أداة: `WebApplication`/`SoftwareApplication` (مجاني، `offers.price = 0`) + `BreadcrumbList`.

### 6.2 مكتبة القواعد (~80 قاعدة × لغتين)
`/rules/<rule-id>` لكل قاعدة: الشرح، لماذا يهم، مثال حي، طريقة الاكتشاف، المراجع (WCAG، W3C Arabic Layout
Requirements). كل مخالفة في أي تقرير تربط هنا → ربط داخلي كثيف.

### 6.3 المحتوى العربي الأول (فجوة حقيقية في السوق)
- **`/learn`**: أدلة تقنية بالعربية (قليلة جداً على الويب العربي) — مرتبطة بخطة محتوى كلاود توبيا.
- **`/fix`**: دليل لكل رسالة خطأ في Search Console وMerchant Center، **بالعربي** — الناس يلصقون رسالة
  الخطأ في جوجل حرفياً؛ صفحة لكل رسالة = زيارات مستمرة.
- **`/glossary`**: مسرد مصطلحات SEO والويب بالعربي (صفحة لكل مصطلح).
- صفحات مقارنة صادقة: «Arablyzer مقابل Semrush Site Audit» إلخ — بجدول حقائق قابل للتحقق فقط.

### 6.4 الروابط الخلفية (آلة السلطة)
| المصدر | الآلية |
|---|---|
| التقرير السنوي + البيانات المفتوحة | صحفيون وجامعات ومدوّنات تستشهد بالأرقام → روابط من نطاقات قوية. صفحة إحصاءات قابلة للاقتباس لكل رقم |
| GitHub + npm + Chrome Web Store + أدلة MCP (mcpservers.org، Glama) | روابط وأدلة مطوّرين (كاشف مدرج هناك — نحن أيضاً) |
| متاجر تطبيقات سلة وزد | إدراج بروابط وجمهور تجّار مباشر |
| إطلاقات | Product Hunt، Show HN، مجتمعات المطورين العرب، AlternativeTo، قوائم awesome على GitHub |
| الشارة | روابط علامة تجارية طبيعية من مواقع تجتاز الفحص |
| Hugging Face / Kaggle | نشر البيانات السنوية مع رابط المنهجية |
| كلاود توبيا | «بناه كلاود توبيا» في التذييل — والعكس من صفحة المختبر والمقالات |

### 6.5 الـ SEO التقني (يجب أن يكون مثالياً — نحن أداة SEO)
- **Astro ثابت**، JavaScript فقط في جزر الأدوات؛ هدف Lighthouse 100 في كل الفئات؛ Core Web Vitals
  «جيد» في بيانات المستخدمين الحقيقية.
- `hreflang` كامل (ar، en، x-default→ar) ومتبادل، `canonical` لكل صفحة، sitemap index مقسّم
  (tools/rules/learn/fix/glossary/report)، **IndexNow** لـ Bing وYandex عند كل نشر.
- **تقارير المستخدمين `noindex` دائماً** (منع صفحات رقيقة/مكررة/محتوى مستخدمين). لا صفحات
  «فحص موقع X» مولّدة آلياً للأرشفة (doorway pages).
- صور OG تلقائية لكل صفحة؛ خطوط مقسّمة (subset) ومحمّلة مسبقاً؛ لا layout shift.
- Arablyzer يفحص نفسه في CI ويجب أن يجتاز 100% من الفحوص الآلية.

### 6.6 القياس من اليوم الأول
Google Search Console + Bing Webmaster Tools مربوطان **قبل الإطلاق** (درس من cloudtopia.net حيث لم يكونا
مربوطين)؛ تحليلات تحترم الخصوصية (Plausible أو Umami مستضاف ذاتياً)؛ تتبّع ترتيب لعناقيد البحث المستهدفة؛
لوحة شهرية: صفحات مؤرشفة، نطاقات مُحيلة، نقرات من البحث، استخدام كل أداة، التحويل إلى حساب/اشتراك/lead.

## 10. محرّك القواعد

```ts
export interface Rule {
  id: string                    // 'ar-letter-spacing' — ثابت للأبد
  version: string               // semver للقاعدة
  category: 'crawl' | 'index' | 'onpage' | 'links' | 'schema' | 'intl' | 'speed'
          | 'commerce' | 'ai' | 'trust' | 'ar-render' | 'rtl' | 'ar-content'
          | 'forms' | 'locale'
  severity: 'critical' | 'serious' | 'moderate' | 'minor' | 'info'
  wcag?: string[]
  appliesTo: (page: PageFacts) => boolean
  needs: CollectorId[]
  detect: (evidence: Evidence) => Finding[]   // دالة نقية — تُختبر بلا متصفح
  copy: { ar: RuleCopy; en: RuleCopy }
  manualCheck?: boolean                       // «يحتاج مراجعة بشرية» — لا يُخصم
}
```

- **Collectors** (داخل الصفحة) تجمع حقائق خاماً فقط؛ **Detectors** دوال نقية تحوّلها لمخالفات بدليل؛
  **Scoring** بأوزان منشورة، ودرجات قابلة للمقارنة فقط داخل نفس الإصدار الرئيسي للقواعد.
- **أداة = مجموعة قواعد + قالب صفحة** (`packages/tools`)؛ الفحص الكامل = اتحاد القواعد المناسبة.
- **لا تُدمج قاعدة** دون: fixture «خطأ» يفشل + fixture «صحيح» ينجح + اختبار وحدة + نص عربي مراجَع +
  صفحة في مكتبة القواعد.

## 12. الذكاء الاصطناعي (Claude)

**الاستخدامات:** (1) **مساعد الإصلاح** عند الطلب فقط: القاعدة + الدليل الحقيقي → شرح عربي مخصّص +
مقتطف إصلاح؛ (2) **مفكك الأخطاء** عند غياب دليل مكتوب مسبقاً لرسالة ما (مع تعليم «مولّد»)؛
(3) **تصنيف الزحف السنوي** [v3].

**الإعدادات:**
- النموذج الافتراضي **`claude-opus-5`** مع `thinking: { type: "adaptive" }`.
- **مخرجات منظّمة** (`output_config.format` بمخطط JSON ثابت: `explanation_ar`، `explanation_en`،
  `steps[]`، `patch`، `confidence`) عبر `client.messages.parse()`.
- **كاش المطالبات** (الثابت أولاً مع `cache_control`) + **كاش النتائج** بمفتاح (rule id، نسخة القاعدة،
  hash الدليل، اللغة).
- **Batch API** (خصم 50%) للزحف السنوي.
- التحقق من `stop_reason` قبل قراءة المحتوى؛ للطلبات الفورية: احتياط من جهة الخادم
  (`fallbacks: "default"` مع رأس `server-side-fallback-2026-07-01`) — **غير مدعوم في Batch API**.
- ⚠️ نموذج أرخص (`claude-haiku-4-5`) للتصنيف الجماعي **قرار المالك** بعد تقييم على عيّنة.

**الضوابط:**
- لا يخترع أرقاماً ولا يغيّر الدرجة ولا يضيف مخالفات.
- يُعلَّم «مولّد بالذكاء الاصطناعي — راجعه قبل التطبيق».
- ميزانية لكل فحص ومستخدم وخطة.
- محتوى الصفحة المفحوصة **بيانات غير موثوقة** داخل وسوم واضحة (ضد حقن المطالبات).
- مجموعة تقييم ثابتة قبل أي تغيير في المطالبة أو النموذج.

## 13. الأمن ومنع الإساءة

- **SSRF:** كل حركة المتصفح وكل `fetch` في الخادم عبر **Smokescreen** (يمنع RFC1918، loopback،
  link-local، CGNAT، `169.254.169.254`، IPv6 الخاصة) **بعد** حل DNS — يحمي من DNS rebinding والتحويل إلى
  عناوين داخلية؛ تحقق مسبق في الـ API أيضاً؛ منافذ 80/443 فقط.
- **عزل المتصفح:** حاوية بلا صلاحيات، مستخدم غير root، نظام ملفات للقراءة فقط، حدود ذاكرة/CPU، شبكة
  لا ترى إلا Smokescreen، سياق جديد لكل فحص.
- **الحدود:** Turnstile على الفحص المجهول؛ حدود Cloudflare لكل IP؛ token bucket في Valkey؛ حصص الخطط؛
  حد لكل نطاق مستهدف.
- **النماذج:** اختبار نماذج الإدخال يستخدم `checkValidity()` فقط — **لا submit، لا Enter، لا نقر على أزرار**.
- **لا تجاوز لـ CAPTCHA أو حماية البوتات أبداً** → «الموقع حجب الفحص» بصدق.
- **الأسرار:** متغيرات بيئة Coolify فقط؛ مفاتيح API المستخدمين مُجزّأة؛ Webhooks الدفع موقّعة ومتحقق منها.
- **robots.txt:** الفحص الفردي بطلب المستخدم = زيارة متصفح بـ User-Agent معرّف؛ الزحف العميق والسنوي
  يحترمان robots.txt؛ `/bot` تشرح البوت وتتيح opt-out.
- **مراجعة أمنية** قبل الإطلاق مع اختبارات SSRF آلية في CI.

- لا نخزّن ترويسات أو كوكيز المستخدم؛ سجلات IP لحدود المعدل فقط وتُحذف خلال أيام؛ اللقطات تُحذف بعد

### 18.3.1 على سيرفرك الحالي

إذا شُغّل Arablyzer على سيرفر موجود: التكلفة الإضافية في الإطلاق ≈ **النطاق فقط (~$1/شهر)** + ما يلزم من
الذكاء الاصطناعي (صفر إن أُطفئ، أو دولارات قليلة بنموذج رخيص). الشروط:
- **حدود موارد للحاويات** (CPU/RAM) حتى لا تبطئ المتصفحات المواقع الأخرى على نفس السيرفر.
- **شبكة معزولة** للعمّال لا ترى إلا بروكسي الخروج (Smokescreen) — لا وصول لقواعد بيانات أو لوحات
  إدارة أو خدمات أخرى على السيرفر (هذا أهم شرط أمني، القسم 13).
- مقياس للنقل: عند تجاوز انتظار الطابور 30 ثانية أو تأثّر المواقع الأخرى → عامل على سيرفر منفصل.
- **التحجيم على سيرفر مشترك (8 vCPU / 16GB، عليه خدمات أخرى):** الذاكرة هي القيد لا المعالج. ميزانية
  Arablyzer ≈ 3.5GB: عاملا متصفح (حد 1.2GB لكل منهما)، عامل fetch (256MB)، API (256MB)، Valkey (128MB)،
  Postgres خاص (512MB)، Smokescreen (64MB). السعة ≈ 80–120 فحصاً كاملاً/ساعة (~2,000–2,800/يوم نظرياً)،
  والأدوات الخفيفة آلاف في الساعة.
- **قائمة المنع في بروكسي الخروج تشمل عنوان IP العام للسيرفر نفسه** (عبره يمكن الوصول إلى منافذ خدمات
  السيرفر الأخرى من الداخل حتى لو كان الجدار الناري يحجبها من الخارج)، وكل نطاقات شبكات Docker وWireGuard
  وIPv6 الخاصة.

- تكاليف النمو (~$350–430) ← **~32–40 مشتركاً** (أو ~16–23 مع Haiku).

### 18.5 ضبط التكاليف (جزء من التصميم)

1. **مجموعتا عمّال:** `fetch` بلا متصفح لأغلب الأدوات، و`browser` فقط للعرض وLighthouse والنماذج.
2. **كاش النتائج** لكل (رابط، أداة، نسخة القواعد) 15–30 دقيقة + دمج الفحوص المتطابقة الجارية.
3. **«كيف تُصلح» ثابت لكل قاعدة** يُكتب مرة واحدة؛ الذكاء الاصطناعي فقط لرقعة مخصّصة عند الطلب، بحصة
   لكل خطة؛ Haiku للأعمال الجماعية بعد التقييم.
4. **حدّ إنفاق** في Anthropic Console + تنبيه تكلفة يومي؛ تنبيهات فوترة Cloudflare.
5. **اللقطات WebP** مع قواعد دورة حياة في R2: 30 يوماً للمجاني، أطول لـ Pro.
6. **خادم واحد في البداية** (Compose)، وإضافة عمّال عندما يتجاوز انتظار الطابور (p95) 30 ثانية.
7. **قابلية النقل:** كل شيء في Docker؛ الانتقال بين Hetzner وHostinger (حسابك الحالي) بلا تغيير كود.

## 22. برومبت البدء لـ Claude Code

أنشئ مستودعاً فارغاً `arablyzer`، ضع هذه الوثيقة فيه كـ `docs/BUILD-PLAN.md`، ثم افتح Claude Code فيه
والصق:

```
You are the lead engineer for Arablyzer — an open-source (AGPL-3.0) website
analyzer for Arabic and Gulf websites, built by CloudTopia (LAB-001 of
CloudTopia Labs). Think "Shipwork-style toolbox of ~110 free single-purpose
checks" plus a deep Arabic layer nobody else has: cross-engine Arabic
rendering, Arabic fonts, RTL, Arabic forms, Arabic-aware SEO, Gulf e-commerce
(Salla/Zid, 3-decimal currencies), WhatsApp. The hosted site is free by
default with paid plans only for heavy use. SEO is the product: every tool is
its own indexable, genuinely working page in Arabic (root) and English (/en).

Read docs/BUILD-PLAN.md end to end before anything else. It is the source of
truth for scope, stack, SEO rules, security rules, plans and phases. Then:

1. Work phase by phase (section 17). Start with Phase 0 only.
2. Before coding a phase, post a short design (files, packages, first rules,
   risks) and wait for my approval.
3. TDD for every rule: the "wrong" fixture first, then the "right" fixture,
   then the detector. A rule is not done without both fixtures, a unit test,
   reviewed Arabic copy, and its rule-library page.
4. Every tool page must pass the tool-page SEO template (section 6.1) and the
   self-audit in CI. Arabic is the original language; slugs are ASCII.
   User reports are always noindex. Never generate doorway pages.
5. Security (section 13) is non-negotiable: no scan traffic may bypass the
   egress proxy; never submit forms; never bypass CAPTCHAs or bot protection.
6. Plans and quotas live in packages/plans and are enforced in the API. Free
   single-page tools stay free and signup-free.
7. Never invent numbers in UI copy, READMEs, seed data, pricing, or reports.
8. Never deploy, publish data, register domains, set up payments, or crawl
   third-party sites in bulk without my explicit approval. Single scans of
   sites I name are fine.
9. Ask me about every item in section 20 when it becomes relevant — do not
   decide those yourself.
10. One PR per phase milestone, small reviewable commits; update the plan's
    "measured" sections (costs, SLOs) with real numbers as you get them.
```
