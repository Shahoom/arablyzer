# مؤشرات أداء الويب الأساسية (Core Web Vitals)

مؤشرات أداء الويب الأساسية ثلاثة مقاييس من Google لتجربة الزوار الحقيقيين مع الصفحة: التحميل (LCP) والاستجابة (INP) والثبات البصري (CLS).

## التعريف

- مؤشرات أداء الويب الأساسية (Core Web Vitals) هي الجزء من مبادرة Web Vitals في Google الذي ينطبق على كل صفحات الويب، وينبغي أن يقيسه كل صاحب موقع، وتعرضه أدوات Google.
- المجموعة الحالية: سرعة عرض أكبر محتوى مرئي (LCP) للتحميل، ومدى استجابة الصفحة لتفاعلات المستخدم (INP) للاستجابة، ومتغيّرات التصميم التراكمية (CLS) للثبات البصري. وقد حلّ INP محل مقياس First Input Delay (FID) في 2024.
- ولكل منها حدود تُقاس عند الشريحة المئوية 75 من مرات تحميل الصفحة، على الجوال والحاسوب كلاً على حدة:

| المقياس | جيد | ضعيف |
|---|---|---|
| LCP | 2.5 ثانية أو أقل | أكثر من 4 ثوانٍ |
| INP | 200 ملّي ثانية أو أقل | أكثر من 500 ملّي ثانية |
| CLS | 0.1 أو أقل | أكثر من 0.25 |

والقيمة بين الحدين تحتاج إلى تحسين. وتجتاز الصفحة التقييم إذا كانت المقاييس الثلاثة جيدة عند الشريحة المئوية 75.

## لماذا يهم

- تستخدم أنظمة الترتيب في Google مؤشرات أداء الويب الأساسية، لكن النتائج الجيدة لا تضمن الصدارة: يظل Google يعرض المحتوى الأكثر صلة بالبحث، حتى لو كانت تجربة صفحته أضعف.
- هي مقاييس ميدانية تُسجَّل من زوار حقيقيين على أجهزتهم وشبكاتهم. أما أدوات المختبر مثل Lighthouse فلا تقيس INP، إذ لا أحد يتفاعل مع الصفحة، ويقترح web.dev مقياس Total Blocking Time (TBT) بديلاً عنه.
- البيانات الميدانية في PageSpeed Insights وتقرير Core Web Vitals في Search Console تأتي من تقرير تجربة مستخدمي Chrome (CrUX)، ومنه تقرأ قواعد Arablyzer أيضاً، على الجوال.

## مثال

قياس المقاييس الثلاثة في صفحاتك بمكتبة `web-vitals`، وهي أسهل طريقة لذلك بحسب web.dev:

```js
import {onCLS, onINP, onLCP} from 'web-vitals';

function send(metric) {
  navigator.sendBeacon('/analytics', JSON.stringify(metric));
}

onCLS(send);
onINP(send);
onLCP(send);
```

## أخطاء شائعة

- الحكم على الصفحة بتجربة مختبر واحدة، وقد تختلف عمّا يعيشه الزوار، ولا تقيس INP.
- قراءة المتوسط بدل الشريحة المئوية 75، أو خلط الجوال بالحاسوب.
