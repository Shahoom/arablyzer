# فحص صفحة المنتج

يتحقق من أن بيانات المنتج المنظّمة في صفحتك فيها سعر وعملة بالصيغة التي يطلبها Google، وأن أسعار الريال العماني والدينارين الكويتي والبحريني بثلاث منازل عشرية.

## ماذا تفحص

- أن لكل عرض (`Offer`) لمنتج في JSON-LD سعراً: `price` أو `priceSpecification.price`، أو `lowPrice` للعرض المجمّع (`AggregateOffer`).
- أن السعر في البيانات بالأرقام 0–9 مع النقطة للكسر العشري، لا بالأرقام العربية المشرقية ولا مع رمز العملة.
- أن لكل عرض عملة في `priceCurrency` برمزها من ثلاثة أحرف حسب ISO 4217، مثل `OMR` أو `SAR`، لا «ر.ع.».
- أن أسعار الريال العماني والدينار الكويتي والدينار البحريني في نص الصفحة مكتوبة بثلاث منازل عشرية، مثل «12.500 ر.ع.».

## مثال

### خطأ

```html
<!doctype html>
<html lang="ar" dir="rtl">
  <head>
    <script type="application/ld+json">
      {
        "@context": "https://schema.org",
        "@type": "Product",
        "name": "عطر العود الملكي",
        "offers": {
          "@type": "Offer",
          "price": "١٢٫٥٠٠",
          "priceCurrency": "ر.ع."
        }
      }
    </script>
  </head>
  <body>
    <h1>عطر العود الملكي</h1>
    <p>السعر: 12.50 ر.ع.</p>
  </body>
</html>
```

### صحيح

```html
<!doctype html>
<html lang="ar" dir="rtl">
  <head>
    <script type="application/ld+json">
      {
        "@context": "https://schema.org",
        "@type": "Product",
        "name": "عطر العود الملكي",
        "offers": {
          "@type": "Offer",
          "price": "12.500",
          "priceCurrency": "OMR"
        }
      }
    </script>
  </head>
  <body>
    <h1>عطر العود الملكي</h1>
    <p>السعر: 12.500 ر.ع.</p>
  </body>
</html>
```

## كيف تُصلح

ولِّد كتلة JSON-LD من قيمة السعر المخزّنة في قاعدة البيانات، لا من النص المنسّق للصفحة، واكتب السعر على الصفحة بمنازل عملته:

```html
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Product",
    "name": "عطر العود الملكي",
    "offers": {
      "@type": "Offer",
      "price": "12.500",
      "priceCurrency": "OMR",
      "availability": "https://schema.org/InStock"
    }
  }
</script>
<p>السعر: 12.500 ر.ع.</p>
```

- اكتب السعر في البيانات بالأرقام 0–9 والنقطة، بلا فواصل آلاف ولا رمز عملة: `"price": "12.500"` أو `"price": 12.5`.
- ضع العملة في `priceCurrency` برمزها: `OMR` للريال العماني، و`SAR` للريال السعودي، و`AED` للدرهم الإماراتي، و`KWD` للدينار الكويتي، و`BHD` للدينار البحريني، و`QAR` للريال القطري.
- للمنتج الذي له عدة أسعار (`AggregateOffer`) اكتب `lowPrice`، و`highPrice` إن شئت، مع `priceCurrency`.
- في إعدادات العملة في منصة متجرك اجعل عدد المنازل العشرية ثلاثاً للريال العماني والدينارين الكويتي والبحريني.
- بعد الإصلاح اختبر الصفحة في أداة Google لاختبار النتائج المنسّقة.

## أسئلة شائعة

### لماذا لا أكتب السعر في البيانات كما يظهر على الصفحة؟

لأن Schema.org يطلب السعر بالأرقام 0–9 لا برموز تشبهها، وبالنقطة فاصلاً عشرياً، والعملة في `priceCurrency` لا داخل السعر. فالسعر المنسّق للقارئ العربي، بالأرقام العربية المشرقية ومعه «ر.ع.»، صحيح على الصفحة، لكنه في البيانات لا يوافق ما يطلبه Schema.org.

### هل تظهر أسعاري في نتائج Google إذا نجحت الصفحة؟

ليس بالضرورة. النجاح يعني أن السعر والعملة مكتوبان كما يطلب Google، ويقول Google إن الخصائص المطلوبة شرط لتكون الصفحة مؤهلة للنتائج المنسّقة. لكن الأداة تفحص السعر والعملة وحدهما، لا بقية خصائص المنتج، فاختبر الصفحة أيضاً في أداة Google لاختبار النتائج المنسّقة.

### بيانات متجري مكتوبة بـ Microdata، فهل تفحصها الأداة؟

لا. تقرأ الأداة كتل JSON-LD وحدها، ولا تفحص البيانات المكتوبة بـ Microdata أو RDFa، ولا الكتل التي تضيفها السكربتات بعد تحميل الصفحة. ولا تفحص المنتج الذي بلا عروض، لأن Google يقبل بدلها المراجعات أو التقييم.

## المنهجية

نجلب الصفحة باسم `ArablyzerBot`، ونتبع تحويلاتها، ونقرأ HTML كما يرسله الخادم، قبل تشغيل JavaScript. نقرأ فيه كل كتلة JSON-LD صالحة، بما فيها `@graph`، ونجد المنتجات بنوعها: `Product` وأنواعه الأخص في Schema.org. لكل عرض نبحث عن السعر في `price` أو `priceSpecification.price` أو `lowPrice`، وعن العملة في `priceCurrency`، ونقبل السعر رقماً أو نصاً من الأرقام 0–9 فيه نقطة واحدة على الأكثر، والعملة رمزاً من قائمة ISO 4217 كما تنشرها الجهة المسؤولة عنها. ثم نقرأ النص المرئي ونجد فيه الأسعار بالريال العماني والدينارين الكويتي والبحريني، وهي أرقام تجاورها علامة العملة قبلها أو بعدها، ونبلّغ عن أول سعر في كل عملة بعد فاصله العشري رقم واحد أو رقمان. تعطي الصفحة نفسها النتيجة نفسها في كل فحص.
