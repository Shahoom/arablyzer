# فحص إمكانية الوصول

يفحص صفحتك في ثلاثة متصفحات بقواعد مختارة من axe-core حسب WCAG 2.2: أسماء الأزرار والروابط، والنص البديل للصور، وتباين النص، ومنه العربي، ورموز اللغة.

## ماذا تفحص

- أن لكل زر `<button>` اسماً يقرؤه قارئ الشاشة: نصاً، أو `aria-label` أو `aria-labelledby` أو `title` (المعيار 4.1.2).
- أن لكل رابط اسماً: نصاً، أو `alt` لصورته، أو `aria-label` أو `aria-labelledby` أو `title` (المعياران 2.4.4 و4.1.2).
- أن لكل صورة نصاً بديلاً، أو أنها معلَّمة للزينة بـ `alt=""` أو `role="presentation"` (المعيار 1.1.1).
- أن تباين النص مع خلفيته 4.5:1 على الأقل، أو 3:1 للنص الكبير، والنص العربي منه (المعيار 1.4.3).
- النص الذي لا يمكن قياس تباينه، فوق الصور والتدرّجات أو تحت عناصر أخرى، لتراجعه بعينك.
- أن كل سمة `lang` داخل الصفحة رمز لغة صحيح، مثل `en` لا `english` (المعيار 3.1.2).

## مثال

### خطأ

```html
<h1>عطر العود الملكي</h1>
<button id="wishlist" type="button"><svg aria-hidden="true" width="16" height="16" viewBox="0 0 16 16"><circle cx="8" cy="8" r="8" /></svg></button>
```

### صحيح

```html
<h1>عطر العود الملكي</h1>
<button id="wishlist" type="button" aria-label="أضف إلى المفضلة"><svg aria-hidden="true" width="16" height="16" viewBox="0 0 16 16"><circle cx="8" cy="8" r="8" /></svg></button>
<button type="button">أضف إلى السلة</button>
```

## كيف تُصلح

أعطِ كل زر ورابط اسماً بلغة الصفحة، ولكل صورة نصاً بديلاً، وأعلن لغة كل مقطع بلغة أخرى برمزها:

```html
<button type="button" aria-label="أضف إلى المفضلة">
  <svg aria-hidden="true" width="16" height="16" viewBox="0 0 16 16"><circle cx="8" cy="8" r="8" /></svg>
</button>
<a href="/cart" aria-label="السلة">
  <svg aria-hidden="true" width="16" height="16" viewBox="0 0 16 16"><rect width="16" height="16" /></svg>
</a>
<img src="oud.jpg" alt="زجاجة عطر العود الملكي، 50 مل" />
<img src="divider.png" alt="" />
<p>الدفع متاح بـ <span lang="en">Apple Pay</span></p>
```

- أبقِ `aria-hidden="true"` على الأيقونة نفسها، فلا تُقرأ مرتين، واكتب `alt=""` فارغاً للصورة التي للزينة فقط، فيتجاوزها قارئ الشاشة.
- اجعل النص أغمق أو الخلفية أفتح حتى يبلغ التباين 4.5:1؛ وعلى الأبيض، `#767676` أفتح رمادي يبلغها. وراجع ألوان النصوص المؤقتة في الحقول وألوان الروابط أيضاً.
- للنص فوق صورة ضع بينهما طبقة لونها ثابت أو شبه شفاف، مثل `background: rgb(0 0 0 / 60%)` خلف النص الأبيض، أو انقل النص إلى خلفية سادة.

## أسئلة شائعة

### هل تعني النتيجة الناجحة أن صفحتي متوافقة مع WCAG؟

لا. تشغّل الأداة خمس قواعد مختارة من axe-core، وكثير من معايير WCAG 2.2 يحتاج حكم إنسان، مثل أن يصف النص البديل ما في الصورة فعلاً. النتيجة الناجحة تعني أن الصفحة خالية مما تفحصه هذه القواعد في المتصفحات الثلاثة.

### هل تفحص الأداة تباين النص العربي؟

نعم. محرّك axe-core، الذي تقوم عليه أدوات كثيرة لفحص إمكانية الوصول، يترك النص العربي: يظن الجمل العربية حروفاً مركّبة من خطوط الأيقونات، وبعد ثلاث جمل منها يترك كل النص الذي بالخط نفسه. نخبره قبل أن يعمل أن خطوط النص العربي ليست خطوط أيقونات، فيقيس تباين النص العربي كغيره.

### لماذا تطلب الأداة أن أراجع بعض النصوص بنفسي؟

لأن axe-core لا يستطيع قياس تباين النص الذي فوق صورة أو تدرّج لوني، أو الذي يغطيه عنصر آخر، فنعرضه لتفحصه بعينك مع السبب. متطلب التباين في WCAG 2.2 ينطبق عليه أيضاً، لكن هذه النتيجة لا تُنقص الدرجة.

## المنهجية

نجلب الصفحة باسم `ArablyzerBot`، ونتبع تحويلاتها، ثم نعرضها في Chromium وFirefox وWebKit، كل منها خلف بروكسي الخروج في Arablyzer، ونشغّل في كل محرّك قواعد axe-core 4.13.0: `button-name` و`link-name` و`image-alt` و`color-contrast` و`valid-lang`. قبل أن يعمل axe نخبره أن خطوط النص العربي ليست خطوط أيقونات، فيقيس تباين النص العربي أيضاً. نذكر كل عنصر مخالف مرة واحدة، مع المحرّكات التي وجدته. والنص الذي لم يستطع axe قياس تباينه نعرضه للمراجعة، ولا يُنقص الدرجة. تعطي الصفحة نفسها النتيجة نفسها في كل فحص.
