# فحص البيانات المنظّمة (JSON-LD)

يتحقق من أن كتل JSON-LD في صفحتك مكتوبة بصيغة JSON صالحة يقرؤها Google، وأن لكل عرض منتج فيها سعراً مكتوباً بالأرقام 0–9 وعملة برمز من ثلاثة أحرف، مثل OMR أو SAR.

## ماذا تفحص

- أن كل كتلة `<script type="application/ld+json">` مكتوبة بصيغة JSON صالحة، وإن لم تكن فنذكر نوع الخطأ وموضعه: فاصلة زائدة، أو علامة تنصيص غير مهرّبة، أو سطر جديد داخل نص.
- أن لكل عرض في منتج سعراً: `price` أو `priceSpecification.price` في العرض (`Offer`)، و`lowPrice` في العرض المجمّع (`AggregateOffer`).
- أن السعر مكتوب بالأرقام 0–9 مع النقطة للكسر العشري، لا بالأرقام العربية المشرقية مثل `١٢٫٥٠٠`، ولا مع رمز العملة.
- أن لكل عرض عملة في `priceCurrency`، برمز من ثلاثة أحرف حسب ISO 4217، مثل `OMR` أو `SAR`، لا `ر.ع.` أو `ر.س`.

## مثال

### خطأ

```html
<!doctype html>
<html lang="ar" dir="rtl">
  <head>
    <title>عطر العود الملكي | متجر الواحة</title>
    <script type="application/ld+json">
      {
        "@context": "https://schema.org",
        "@type": "Product",
        "name": "عطر العود الملكي",
        "offers": {
          "@type": "Offer",
          "price": "١٢٫٥٠٠",
          "priceCurrency": "ر.ع."
        }
      }
    </script>
  </head>
  <body>
    <h1>عطر العود الملكي</h1>
    <p>السعر: ١٢٫٥٠٠ ر.ع.</p>
  </body>
</html>
```

### صحيح

```html
<!doctype html>
<html lang="ar" dir="rtl">
  <head>
    <title>عطر العود الملكي | متجر الواحة</title>
    <script type="application/ld+json">
      {
        "@context": "https://schema.org",
        "@type": "Product",
        "name": "عطر العود الملكي",
        "offers": {
          "@type": "Offer",
          "price": "12.500",
          "priceCurrency": "OMR"
        }
      }
    </script>
  </head>
  <body>
    <h1>عطر العود الملكي</h1>
    <p>السعر: ١٢٫٥٠٠ ر.ع.</p>
  </body>
</html>
```

## كيف تُصلح

اكتب السعر في البيانات بالأرقام 0–9 والنقطة، وضع العملة في `priceCurrency` برمزها، واكتب النصوص بحيث لا تكسر JSON:

```html
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "Product",
    "name": "بخور «ظفار» الفاخر",
    "offers": {
      "@type": "Offer",
      "price": "8.500",
      "priceCurrency": "OMR",
      "availability": "https://schema.org/InStock"
    }
  }
</script>
```

- رموز عملات الخليج: `OMR` للريال العماني، و`SAR` للريال السعودي، و`AED` للدرهم الإماراتي، و`KWD` للدينار الكويتي، و`BHD` للدينار البحريني، و`QAR` للريال القطري.
- للمنتج الذي له عدة أسعار (`AggregateOffer`) اكتب `lowPrice`، و`highPrice` إن شئت، مع `priceCurrency`.
- احذف الفاصلة التي تسبق `}` أو `]`، وهرّب علامة التنصيص داخل النص بكتابتها `\"`، أو استخدم علامتي التنصيص العربيتين «» اللتين لا تحتاجان إلى تهريب.
- الأفضل أن تولِّد الكتلة بدالة ترميز JSON، مثل `JSON.stringify` في JavaScript أو `json_encode` في PHP، ومن قيمة السعر المخزّنة في قاعدة البيانات، لا من النص المنسّق للعرض على الصفحة.
- بعد الإصلاح اختبر الصفحة في أداة Google لاختبار النتائج المنسّقة.

## أسئلة شائعة

### السعر على صفحتي «`١٢٫٥٠٠ ر.ع.`»، فلماذا يُعدّ خطأً في البيانات؟

لأن Schema.org يطلب أن يُكتب السعر في البيانات بالأرقام 0–9 والنقطة فاصلاً عشرياً، وأن توضع العملة في `priceCurrency` لا رمزاً داخل السعر. الصيغة العربية صحيحة على الصفحة للقارئ، أما البيانات فتقرؤها البرامج: اكتب فيها `"price": "12.500"` و`"priceCurrency": "OMR"`، واترك السعر المعروض كما هو.

### ماذا يحدث إذا كان في كتلة JSON-LD خطأ واحد؟

لا يستطيع Google قراءة أي شيء منها: تُهمَل الكتلة كلها، لا السطر الخاطئ وحده، ويعرض Search Console هذه الحالة في تقرير البيانات المنظّمة غير القابلة للتحليل (Unparsable structured data). لذلك نذكر أول خطأ في كل كتلة، وموضعه بالسطر والعمود.

### هل تغني الأداة عن أداة Google لاختبار النتائج المنسّقة؟

لا. تفحص الأداة صيغة JSON وسعر المنتج وعملته فقط؛ أما صحة الأنواع والخصائص الأخرى حسب Schema.org، وأهلية الصفحة للنتائج المنسّقة، فاختبرها في أداة Google لاختبار النتائج المنسّقة أو في مدقق Schema.org.

## المنهجية

نجلب الصفحة باسم `ArablyzerBot`، ونتبع تحويلاتها، ونقرأ HTML كما يرسله الخادم، قبل تشغيل JavaScript؛ فالبيانات التي يضيفها سكربت بعد التحميل لا نراها. نجمع كل وسوم `<script type="application/ld+json">`، بأي حالة أحرف، ونتجاوز الفارغة، ثم نطبّق قاعدتين. الأولى تفحص كل كتلة فحصاً صارماً حسب مواصفة JSON (RFC 8259)، وتذكر أول خطأ فيها بالسطر والعمود. والثانية تقرأ الكتل الصالحة، بما فيها `@graph`، وتجد المنتجات بنوعها: `Product` وأنواعه الأخص في Schema.org، ثم تتحقق من سعر كل عرض وعملته، وتقبل العملة إذا كانت من رموز قائمة ISO 4217. لا نفحص المنتج الذي بلا عروض، ولا البيانات المكتوبة بـ Microdata أو RDFa. وتعطي الصفحة نفسها النتيجة نفسها في كل فحص.
